## P1　用构建标签默认关闭注册码

原则：**代码保留，默认构建（正式版）中注册码完全不存在**；只有显式加构建标签时才编译进去。

1. **Go 后端**：
   - 新增构建标签 **`license`**。所有注册码运行代码（`license.go`、`license_runtime.go`、`license_device*.go`、`license_failure.go`、`license_trace.go`、`license_window_diagnostic.go`、`license_config_*.go` 等）只在 `license` 标签下编译。
   - 默认构建提供一个"已关闭"实现：
     - `/api/license/status` 返回 `{"state":"DISABLED"}`。
     - 业务请求不受授权门禁限制。
     - **不发出任何对授权服务器的网络请求**，不读写 DPAPI 授权缓存。
   - 原 `license_staging` 标签改为必须同时带 `license` 才有效（`license,license_staging`）。
2. **在线更新验签**（R232 引入的更新清单签名与 `updateTrustKeys()`）：
   - 默认构建恢复为 **0.12.76 的更新校验方式**。
   - R232 的签名更新信任放到 `license` 标签下。
   - 账本中写明前后差异，并确认默认构建下在线更新能对现有正式 Latest 正常工作（用 0.12.76 的发布资产做一次本地校验）。
3. **前端**（`backend/web/license-ui.js`、`index.html`、`app.css`）：
   - 状态为 `DISABLED` 时：
     - 遮罩和激活表单永不显示。
     - 主框架直接显示。
     - 不再有 R240 的 `pending` 双隐藏等待。
     - 首屏不得因为授权多等任何时间。
   - 设置页的"授权到期"行不显示。
   - 隐私说明中与注册码相关的段落（R237 定稿句）在默认构建中不出现；`/api/privacy` 恢复为 0.12.76 的内容加上与注册码无关的其他新增内容。
4. **桌面端**（`desktop/main.cjs`、`license-window.cjs`、`license-gate.cjs`、`preload.cjs`）：
   - 授权关闭时，主窗口按 0.12.76 的方式创建和显示：
     - 正常大小、可调整、按 `window-bounds.json` 恢复。
     - 没有 860×580 小窗。
     - 不做透明切换，也不等待授权渲染握手。
   - `requireActiveDesktopLicense` 等门禁在关闭时直接放行。
   - 启动耗时不得比 0.12.76 变差：用 R239/R240 的启动探针做前后交错对比，各 3 次。
5. **安装器**（`installer/`）：默认构建中不出现任何注册码相关的页面或文字。
6. **诊断**：默认构建中不产生 `license_*` 事件；客户端诊断白名单中保留这些事件名，不影响。
7. **构建脚本**：
   - 正式发布脚本使用默认构建（无 `license` 标签）。
   - `scripts/build-license-staging.cjs` 改为同时加 `license,license_staging`，保留供以后使用。
   - 发布检查器（`verify-license-release.cjs` 等）在默认构建下改为检查"**注册码完全不存在**"：
     - 包里没有授权地址、kid、公钥。
     - 后端不发授权请求。
8. **不要删除**任何注册码源码、测试、账本或工单。

# R115 评分与预热、播报复核

日期：2026-09-20。版本：0.12.7。用户明确要求单场评分、能力雷达两者都评估改进。

## 参考来源与边界

核对 LeagueAkari 官方 dev 的 [scoring.ts](https://github.com/LeagueAkari/LeagueAkari/blob/dev/src/shared/data-adapter/analysis/player/scoring.ts)、[constants.ts](https://github.com/LeagueAkari/LeagueAkari/blob/dev/src/shared/data-adapter/analysis/player/constants.ts)、[single/summary.ts](https://github.com/LeagueAkari/LeagueAkari/blob/dev/src/shared/data-adapter/analysis/player/single/summary.ts)、[single/akari.ts](https://github.com/LeagueAkari/LeagueAkari/blob/dev/src/shared/data-adapter/analysis/player/single/akari.ts)。这些是浮动分支链接，不冒充固定提交快照。

值得借鉴的是具名分项、非线性 KDA、有界贡献及完整解释。Akari 的单场公式还包含胜负加分、固定补刀区间、治疗和承伤贡献；这些规则本身不证明统计公平，也不直接适用于本项目所有模式。DL 未复制其实现或原样引入权重；本轮保留已有六项权重，修复比较口径并公开贡献。没有新增上游请求。

**准确性修复与模型选择分开：** 成对样本、未知值不填零、单位不混用、零死亡 KDA 的样本重复不变性，是可测试的正确性要求；新归一化曲线及既有权重属于透明的启发式选择，尚无带真实评价标签的数据集证明其公正性。不能宣称全服能力分或准确段位预测。

## 能力雷达为什么需要改

原实现先累计本人，再尝试寻找对手，导致两边可能不是同一批比赛；多个同位置对手时采用数组第一个，依赖输入顺序。零死亡 KDA 原先跨局求总和后只把总死亡限制为1，重复相同零死亡比赛会抬高数值。某项基准为0时直接删除指标，前端要求七项，因而整张卡消失。旧图形 `clamp(62×本人/对手,16,100)` 有非零保底且较早饱和。

修正后：

- 本人和唯一同位置对手同时存在才成对累计，仍按420/440隔离，至少三场；季快照也跳过无对手记录，新增快照拒绝多个同位置对手。已有快照没有原始全员名单，不能追溯识别历史位置歧义；不伪称完成历史数据重校验。
- KDA 逐场 `(K+A)/max(1,D)` 后平均；DPM/CSM/GPM/VSPM 保持总量除总分钟，参团和伤害占比保持对应总量之比。
- 不可比较的维度返回 `unavailable`，不返回 NaN/Infinity；前端显示横线，其余轴点保留，双方闭合多边形均不画。
- 有效维度图形值为 `100×√本人/(√本人+√对手)`，同值50、真实零0；对手为0不计算相对比值，标记不可比较。该映射为本项目选择，不冒称 Akari 公式。
- 字母等级保持原始比值分档：S≥1.35、A+≥1.20、A≥1.10、A−≥1.03、B+≥0.97、B≥0.90、B−≥0.82、C+≥0.74、C≥0.66，其余C−。图形值和字母等级都不是全服百分位。位置样本并列时按位置键稳定选择标签。

七维布局、排位范围和原始统计值的展示形式保留。原来将“缺一项整图消失”描述为 bug 是因为仍有可用指标；对不可靠的单维不恢复虚构评分。

## 单场评分 v2

原始权重保持 KDA 30%、参团20%、伤害22%、经济8%、补刀12%、视野8%。KDA 为 `(K+A)/max(1,D)`，取消助攻0.8折扣；补刀按真实时长计算，视野仅使用 visionScore，不使用守卫数代替。

常规峡谷队列400/420/430/440/490且十名玩家、双方各五名、五位置完整唯一时，伤害、经济、补刀、视野使用本场同位置组的中位数。KDA和参团仍使用全场中位数。其他队列或位置不完整时全部使用全场中位数，并明确提示。中位数为0时取同一参考组均值；同位置双方均为0则该项中性计分。全场都为0或任一玩家该维度缺失、非有限、负值时，整场剔除该维度，剩余权重重新归一。

每项贡献 `8×归一权重×x/(x+b)`；KDA先对x和b开平方；总分为 `2+Σ贡献`。同值对应6分，不再强迫本场最优玩家接近10分。tooltip 展示原值、参考值、实际权重、贡献及公式。没有胜负直接加分。

使用未舍入分排序；完全同分按 participant ID 稳定排序，表格顺序不影响名次。胜负完整已知时胜方最高分为MVP、败方最高分为SVP；未知结果或重开不给相应徽章，重开不评分。该评价是同场相对表现，不能拿不同局、队列或版本的数字直接比较。

**剩余数据限制：** 前端可以区分缺字段、null、非法值和真实零；但后端部分旧整数模型已把上游缺字段压成0，本轮未大改所有来源协议来恢复丢失信息。全场为0的维度因此统一不评分。未接入新治疗/护盾数据，也未宣称解决了英雄职责、坦克/治疗贡献等全部评价偏差。

## 图片预热结论

现有实现 `champion_images.go` 已有磁盘／内存缓存、同键请求合并、负缓存及容量限制；空闲3秒后预热，前台需求可取消，单轮60秒上限，最多取20个热门英雄详情，再选最多120张装备图，并发槽6。预热仍会增加 OP.GG/DataDragon 流量，并非零成本。

本轮未取得足够的 LeagueAkari 图片预热实现细节，也没有相同网络／Windows下的冷、热缓存对比。因此结论是“本项目已有受控预热，不应重复追加”，**不是“已证明比 LeagueAkari 更快或更好”**。本轮不改图片预热逻辑。

## 阵营播报结论

R115/R113与R68相关回归再次核查，限定原有支持的大乱斗类选人会话、备战席、总开关与单项开启，并经过自定义局暂停及安全会话ID检查；仍用原 `/lol-chat/v1/conversations/{id}/messages`。默认仅自己可见，附带己方英雄须队伍频道；分路缺失省略。有限重试只针对读取，发送结果不确定不重发。

结论是**代码链路和离线模拟通过，未发现明显缺陷；尚未真实 Windows/LCU 发送验收**。这项功能不代表进入实际对局后能按键发聊天，也不保证所有模式支持。

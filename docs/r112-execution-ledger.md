## 实施

- 韩服平均段位先验证公开页的 KR + Riot ID 唯一身份，再用 OP.GG 自身 ID 请求；内部 Riot ID 仍仅作本地缓存关联。
- 按 Flight 根记录的 action 引用读取结果，仅解析平均段位所需字段；兼容对象、空值、`$undefined` 及 Flight 引用。缺少段位的单场不影响其他场次，且仍计入分页覆盖。
- 复用身份、已获取页面和下一页游标；并发合并、90 秒成功缓存、30 秒失败冷却，合法空页也缓存。不会逐人补查 Riot API。
- 临时失败返回 503 / Retry-After，与“来源未提供段位”分开。前端保留待补齐标记，至少 30 秒后只对可见且活动的卡片重试，单轮最多三次尝试；页面重绘不能绕过失败次数上限。
- 修正可见性观察范围与实际查询范围不一致的问题，避免提前取消观察后未加载。
- 新增 `opgg_match_tiers_cost` / `opgg_match_tiers_result`，记录阶段、耗时、页数、缓存命中和匹配数量，不写玩家 ID。
- 离开设置或隐私诊断子页立即恢复“导出诊断日志”。下载带不含路径的关联 ID；完成通知只影响当前页当前导出，迟到、乱序或旧的打开文件夹回调不改变新导出状态。
- 桌面端按关联 ID 保存最多 8 个完成文件，打开对应文件夹；保留同源、同路径、可信发送方及下载链验证。

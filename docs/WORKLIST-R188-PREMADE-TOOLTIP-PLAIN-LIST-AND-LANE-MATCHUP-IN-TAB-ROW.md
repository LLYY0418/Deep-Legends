## P1　组队弹窗：去掉头像，只留文字

### 现状

截图：鼠标移到「组队 ×2」上，弹窗标题「客户端直接给出的组队信息」，下面每人一行：召唤师头像 + 英雄头像（两个圆形叠在一起）+「名字#tag · 英雄」。还没选英雄的人显示「未知英雄」。

代码：`backend/web/gameplay.js` `renderLivePremadeTag`（约 5533 行）生成 `data-tooltip-roster`（含 `profileURL`、`championURL`）；`backend/web/app.js` 约 4034 行把每人渲染成 `tooltip-roster-icons`（两张图）+ 文字；`app.css` 242–247 行是对应样式。

### 修改

1. **不再显示头像。** `renderLivePremadeTag` 的 roster 只保留 `name`、`champion` 两个字段，不再生成 `profileURL` / `championURL`。`app.js` 删除头像渲染分支，删除 `.tooltip-roster-icons` 及其子样式。
2. **每人一行，名字和英雄分开排。** 一行两列：左边名字（`--tooltip-ink`、12px、600 字重，过长省略号），右边英雄名（`--muted`、12px、右对齐、不换行）。行高 22px 左右，行间距 4px。去掉 `·` 连接符。
3. **没选英雄不显示英雄。** 成员 `championId <= 0` 时右边留空，不显示「未知英雄」或「英雄待确认」。随机待定（id < 0）也留空。
4. **标题简化，去掉说明行。** 标题按来源两种：客户端给出的显示 **`组队 2 人`**，推测的显示 **`预组队 2 人`**（数字为实际人数）。删掉「客户端直接给出的组队信息」「最近战绩也支持这一判断」「最近战绩中共同出现至少 N 场」这几句说明（属于口径说明，按用户要求不进界面）。
5. 名字仍走 `maskedPlayerName`，隐藏名字设置下照常打码。
6. 其他使用 `data-tooltip-roster` 的地方（如有）一并改成纯文字版。只有这里在用的话，不保留兼容分支。

### 测试（Node）

1. 两人组队（direct）：弹窗标题 `组队 2 人`，两行，无 `<img>`，没有 `·`。
2. 推测组队：标题 `预组队 3 人`，不出现"最近战绩"字样。
3. 成员 `championId=0`：该行英雄列为空，整个弹窗不出现「未知英雄」「英雄待确认」。
4. 开启隐藏名字：名字被打码。

变异：恢复头像渲染 → 测试 1 FAIL；英雄为 0 时仍输出 `championName` → 测试 3 FAIL。

## P2　对位克制建议移到页签栏右侧，与三个页签同一行

### 现状

`renderLaneMatchupCard`（约 5917 行）把卡片放在「详情」页签内容的最上面（`content.insight`）。推荐区默认停在符文页签，不点「详情」就看不到。用户要求放到右上角，和「符文 / 出装 / 详情」三个页签在同一行。

### 修改

1. **位置。** 从 `content.insight` 里移除。改为渲染进 `.recommendation-tab-row`，放在页签组右侧（行本身已是 `justify-content: space-between`）。切换任何页签都可见。
2. **改成单行紧凑条**（高度与页签组一致，约 44px，不撑高这一行）：
   - 左：敌方英雄小头像（22px）+ `对位 {英雄名}`；
   - 中：有对线胜率时显示结果，例如 `偏劣势 47.6%`（颜色沿用 `is-weak` / `is-strong` / 五五开用 `--ink`），去掉「这局对线」前缀；
   - 右（只在预选、还没锁定时）：最多 3 个候选英雄，各显示 22px 头像 + `+2.1%`，英雄名放在该项的 `aria-label` 和现有 `data-tooltip`（只写英雄名，不写说明）。
   - 去掉卡片标题「对位克制建议」和外层大卡片的内边距，背景、边框沿用 `.recommendation-tabs` 的样式，看起来是同一行的一组控件。
3. **和 `rosterNotice` 共存。** 对位条排在页签组之后、`rosterNotice` 之前；放不下时 `rosterNotice` 换到下一行（现有 1669–1670 行的换行规则保留）。
4. **窄宽度。** 现有 `@media` 断点下（页签组变 `width: 100%` 的那档），对位条换到页签组下面单独一行，占满宽度，内容仍单行；候选英雄超出时只显示前 2 个。
5. **显示时机不变。** 只在选人阶段、对面同路锁定后显示；进入对局后消失。`lane_matchup_card` 诊断保持不变，加一个字段 `placement: "tab-row"`。
6. **不重绘页签组。** 对位数据变化时只替换对位条这个节点（给它一个固定容器 `data-lane-matchup-slot`），不要因为它重建页签按钮，避免切换页签时焦点丢失或闪动。

### 测试（Node）

5. ChampSelect、敌方同路已锁、有对线胜率：对位条出现在 `.recommendation-tab-row` 内、页签组之后；`#recommendation-panel-insight` 里没有对位内容。
6. 当前激活的是符文页签：对位条仍可见。
7. 预选未锁定、有 4 个候选：只显示 3 个；窄宽度下只显示 2 个。
8. 同时有 `rosterNotice`：顺序为 页签组 → 对位条 → notice。
9. 对位数据从 pending 变为成功：页签按钮节点不被替换（引用相同），只更新 `data-lane-matchup-slot`。
10. InProgress：对位条不出现。

变异：对位条仍渲染进 insight 面板 → 测试 5 FAIL；更新时整行重建 → 测试 9 FAIL。

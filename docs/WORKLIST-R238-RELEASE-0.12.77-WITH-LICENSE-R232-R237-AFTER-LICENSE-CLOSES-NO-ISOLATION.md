## P6　设置里的「界面缩放」默认改为自动（用户 2026-10-07 追加）

现状（我读源码确认）：**全新环境本来就是自动**——`index.html` 里 `setting-ui-scale` 第一个选项是 `auto`，`app.js` 用 `preference("ui-scale","auto")`，`desktop/main.cjs` 里 `uiScalePreference = "auto"`。只有用户机器上已经存了固定档（`userData/ui-scale.json` 里 `{mode:"fixed",value}` 或 localStorage）才会显示固定倍率。所以「默认改为自动」真正要做的是下面这条一次性迁移：

1. **一次性迁移**：`ui-scale.json` 没有标记（如 `defaultAuto:1`）时，重置为 `{mode:"auto",defaultAuto:1}`；之后用户自己选的固定档写成 `{mode:"fixed",value,defaultAuto:1}`，不再重置。渲染进程收到外壳回报的 auto 时同步写回 localStorage（外壳值优先，沿用现有 `receiveUiScale` 规则）；浏览器直连预览用 `lol-loot-ui-scale-default-auto` 标记做同样的一次性重置。
2. 如果用户只想要「新装默认自动、老用户保持原档」，就**不做迁移**，账本写明执行的是哪一种（默认按第 1 条）。
3. Node 测试：无文件→自动；`{fixed,1.25}` 无标记→迁移为自动并写标记，再次启动不改；迁移后选 125%→重启仍 125%；损坏文件/超过 1024 字节→自动；localStorage 是固定值但外壳回报 auto→选择框显示「自动」。
4. 变异：改成每次启动都重置 → 「保留用户档位」必须 FAIL；去掉迁移 → 「旧固定档升级后变自动」必须 FAIL。
5. **顺带发现（只报告，不改界面文字和常量）**：设置里写「自动档以 1920×1080 为基准」，但代码 `UI_SCALE_BASE_HEIGHT = 900`（`desktop/ui-scale.cjs` 与 `app.js` 两处一致），实际自动倍率 = `min(宽/1920, 高/900)`，窗口高 990 时自动就是 110%。请在 1920×1080 屏、窗口约占屏幕 92% 时实测自动倍率写进账本，由用户决定改基准还是改文案。
6. 与 R248 的关系：R248 把主窗口恢复为 0.12.76 的创建方式，缩放迁移要在恢复后的窗口流程上验证（`window-bounds.json` 与 `ui-scale.json` 互不影响）。

1. **标签的地图判断没有回退。** R241 的 `matchDataTags` 只看 `match.mapId`（11 / 12 / 30），其他一律当「其他模式」。但后端 `queueModeGroupForLabel` 明确允许 `mapID == 0`（海克斯大乱斗的某些来源），若某条数据路径缺 `mapId`，峡谷对局会丢掉参团/补兵/单杀等标签、大乱斗会丢掉伤转率和好钩。建议：`mapId` 为 0 或缺失时回退到后端已算好的 `match.modeGroup`（排位/灵活/匹配 → 峡谷，大乱斗类 → 大乱斗，斗魂 → 斗魂），并补一条 `mapId=0` 的测试。
2. **赛季头部 60 秒闸门也挡住手动刷新。** R241 P4 的「同账号 60 秒内不发头部请求」对「刷新战绩」按钮同样生效，所以刚打完一局后 60 秒内手动刷新，赛季统计（英雄胜率那块）最多晚 60 秒才含这一局；战绩列表本身不受影响。可以接受，若想让手动刷新绕过闸门，只需让 `fresh` 路径跳过 `recent` 判断，但保留「无新对局就跳过」的小请求。

## 已修改

- `riot_rate_headers.go` 与请求入口：读取 Riot 的 `X-App-Rate-Limit(-Count)`、`X-Method-Rate-Limit(-Count)`；按 host 和接口族维护已消费额度及并发预留；乱序的较低计数不能抹掉本地预留。429 的 Retry-After 共享到对应区域/接口；后台继续让出前台预算。收到实际限额后，Production Key 不再受软件旧 90/2min 上限限制；无有效响应头时保留保守默认。
- 韩服冷开首屏先取 10 场，未完成首屏的自动补齐仍为 10 场。后续分页和已完成页面主动刷新使用设置数量。已有详情、身份缓存和同请求合并继续使用；实查 `championDataCache.loadWithResultTTL` 已有内存、磁盘与 singleflight，未重复加一层相同缓存。
- 新增流式卡片作为绑定根节点时，也绑定展开事件，解决首次点击不响应。
- 页签栏按 key 保留节点、复用头像；选中变化只更新状态，数据进度不强制滚动整个页签栏。详情操作保留卡片摘要、图标、按钮和筛选 hidden 状态，只更新详情；战绩顺序相同时不再逐个移动所有卡片。
- 生涯展示重复数据不重建，相同 URL 图片节点复用。左侧背景只取已回读的客户端当前状态，选英雄、选皮肤都不清空或替换它。局部编辑使渲染缓存失效，确保手动重新读取能撤销草稿并恢复选中状态。
- 导出目录统一为 `export-directory.json`：分享图、诊断日志和设置共用控制器及变更通知。仅首次迁移两个旧设置中最近的有效位置；取消选择保留原位置。分享图也经临时文件和目录身份复核写入；原目录被替换时不直接写入替换目录。

## 头像和旗帜结论

**头像：**日志 1147/1151、2709/2710 行，W5 对另一个已拥有头像的 profile 写入与恢复均为 201 并回读成功。823、866、2686、2789 行的正式操作是 `icon_scope:chat`。本次选择的未拥有头像只能确认聊天/好友栏成功，不能确认或承诺生涯头像成功。界面继续区分这两个范围；选择头像仅选中，按确认才写入。

**旗帜：必须纠正 R108 的契约判断。**实际 regalia 目录中，普通装饰旗帜的 `idSecondary` 为空；非空的 11 个值属于内置 `id:"2"` 的段位档位。客户端 bundle 的 `_setCurrentSelections` 读取 `summary.bannerId`；`selectBanner` 读取事件 `bannerId`；`_savePreferences` 把 `selectedBannerId` 原样放进 `bannerAccent`。应提交 catalog 的字符串 `id`，不是 `idSecondary`。

原代码让普通旗帜在提交前被判 invalid，W6 还可能选中内置段位旗帜作为装饰旗帜探测。现已修正正式写入与探测，同时排除 id 1/2，保留头衔、勋章和边框并要求客户端回读一致。旧测试也按真实契约修正，增加空 secondary、内置段位排除、延迟回读和恢复的覆盖。

日志 1156/2717 行的 W6 为 400 RPC_ERROR，1162/2718 的恢复为 204。原日志没有目标 ID 或请求 body，因此不能据此断言 400 的具体字段，更不能断言所有未拥有旗帜一定能/不能使用。新日志增加 `banner_id` / `requested_banner_id` 与 `catalog-id` 契约标记。正确请求仍需 Windows 客户端实际回读；本机未做该项真机验收。

## Production Key

Riot 官方 Portal 列出的 Personal 限额为 20 次/秒、100 次/两分钟，标准 Production 初始额度为 500 次/10 秒、30,000 次/10 分钟，按区域计算。Production 对多玩家冷开有明显帮助，但不是无限请求；代码以实际响应头为准。

## 根因分析（已读代码，Windows 部分需 GPT 实证）

1. **激活后卡片飘移**：`desktop/license-window.cjs` 的 `setState("ACTIVE")` 直接在可见窗口上 `setBounds(restore)`：窗口从屏幕中间 700×470 变到上次保存的大尺寸和位置，同时页面已经切到"正在读取召唤师信息"面板。Windows 上用户能看到窗口变形移动的全过程，面板跟着窗口一起"飘"。
2. **重启闪出激活卡片**：`backend/web/index.html` 中 `#license-overlay` 默认是**显示**的（没有 `hidden`），`#app-frame` 默认隐藏；`license-ui.js` 要等自己的 `/api/license/status` 返回后才 `apply()` 隐藏遮罩。主进程 `ready-to-show` 只等了**主进程自己**的状态读取（`licenseWindowRead`），没有等页面应用完状态，所以窗口先以正确的大尺寸显示了带空白注册码框的遮罩，约 0.5 秒后才切到主界面。R239 的启动探针只测了窗口**尺寸**，没检查首帧**内容**，所以没发现。
3. **使用中被锁不缩小**：代码路径看上去会调用 `setContentBounds(700×470)`，但 Windows 实机没有生效。最可能的原因是窗口处于**最大化**（或贴边吸附）状态：`unmaximize()` 后立刻 `setContentBounds()`，Windows 随后的还原动作把尺寸改了回去；或 `setResizable(false)` 与尺寸设置的先后顺序在 Windows 上有问题。现有诊断导出里**没有**主进程的"授权窗口状态"记录（只写进 desktop 本地日志），所以从用户日志看不到实际尺寸。需要 GPT 先加诊断，再修复，不能只凭猜测改。
4. **解绑/重置提示"已被其他地方使用"**：客户端只收到 `REPLACED`，`backend/license.go:471` 对 `REPLACED` 固定显示这句。管理员解绑、重置在协议上也表现为 `REPLACED`。

## P1　授权窗口加大（会话 A）

用户反馈 700×470 太小。改为 **内容区 860×580 DIP 固定**，仍不做按屏幕分辨率自适应，屏幕居中、不可最大化、不可拖动改变大小。卡片同比例放大：宽约 480，图标 64×64，标题 24px，输入框高 46，激活按钮高 44，提示/链接 13px；保持 R239 的布局顺序（图标、标题、标签、输入框、一行提示、全宽激活按钮、左右两个链接）和现有文案，**不新增任何说明文字**。隐私说明对话框随窗口放大（最大高度、内部滚动、关闭按钮固定在底部保持不变）。R117 的 CSS 预算不得放宽。

## P2　窗口切换不可见、首帧内容正确（会话 A）

统一规则：**任何授权状态切换导致窗口尺寸变化时，用户都不能看到变形过程，也不能看到错误状态的界面。**

1. **锁定 → 已授权**（激活成功、重输恢复）：先隐藏窗口（或把不透明度设为 0，二选一并写明理由），再恢复保存的大小/位置/最大化，等页面报告"已按 ACTIVE 渲染完成"（页面 `apply()` 后两次 `requestAnimationFrame` 再发通知），再显示。等待上限 1500 ms，超时也显示并记诊断。效果：小窗口消失，大窗口直接以主界面出现，不能看到卡片飘移。
2. **已授权 → 锁定**（使用中被替换/停用/重置/网络到期）：同样先隐藏，切成 860×580 居中，等页面报告"已按锁定状态渲染完成"再显示。
3. **启动首帧**：
   - `index.html` 中遮罩和主框架**默认都隐藏**（例如 `html[data-license="pending"]`，两者都不显示，只有背景色），页面拿到状态后才显示其中一个。
   - 主进程显示主窗口前，必须同时满足：主进程自己读到的状态、页面已按同一状态渲染完成。两者不一致时以主进程（Go 状态）为准再让页面重新应用一次。
   - 已授权用户重启：从 splash 直接到正常大小的主界面（可以出现原有的"正在读取召唤师信息"面板），**不能出现激活卡片**；未授权用户：直接以小窗口显示激活卡片。
4. 页面给主进程的"渲染完成"通知只作为时机信号，**不信任其中的状态值**，主进程仍以带本地 token 读到的 Go 状态为准（沿用 R239 的 IPC 来源校验）。
5. 启动耗时不能变差：按 R239 的 `scripts/r239-startup-probe.cjs` 方法做前后交错对比（ACTIVE、LOCKED 各至少 3 次），并新增**首帧内容**检查：在主窗口第一次 `show` 时立即 `capturePage()`，ACTIVE 时截图里不能有激活表单（用像素/DOM 状态双重判断），LOCKED 时必须是激活表单。

## P3　使用中被锁必须缩成小窗口（会话 A）

1. **先加诊断**：主进程每次授权窗口切换写一条 `license_window_state` 进**诊断导出**（用户点"导出诊断"拿到的 jsonl 里必须能看到），字段至少：from/to 状态、切换前是否最大化/全屏、请求的内容区尺寸、切换后实际 `getContentBounds()`、显示器缩放、耗时、是否重试。不得包含注册码。
2. **修复**：从最大化/全屏/贴边状态锁定时，先退出该状态并等待对应事件（`unmaximize` / `leave-full-screen`，设上限，超时也继续），再设置尺寸；设置后读取实际内容区尺寸，与 860×580 相差超过 2 DIP 时再设置一次并记录。`setResizable(false)` / `setMaximizable(false)` 放在尺寸生效之后。
3. **锁定前的大小要记住**：从最大化状态被锁，重新激活后恢复为最大化；从普通大小被锁，恢复原大小和位置（沿用 R239 的不写入 `window-bounds.json` 规则，锁定期间的小尺寸绝不保存）。
4. **测试**：
   - 纯模块测试覆盖：普通→锁定→激活、最大化→锁定→激活、全屏→锁定→激活、`unmaximize` 事件不来（超时）、第一次设置被系统改回（重试）。
   - Windows 真实窗口：在现有 Windows CI 任务里加一个 Electron 真实窗口用例（最大化后切锁定，断言实际内容区为 860×580；再激活断言恢复最大化）。本地没有 Windows 时如实写"已加入 CI，未在远端跑"，不要写成通过。
   - 用 R239 的变异方法再加一项变异：去掉"等待 unmaximize"，确认新用例失败。

## P4　"已被其他地方使用"文案与启动双续租（会话 A）

1. `REPLACED` 的提示改为：**"注册码已在其他设备使用或已被重置"**。不改协议、不新增错误码（发布前不动协议）。`REVOKED` 仍为"注册码已停用"。同步更新所有引用该句的测试/快照。
2. 启动双续租：找出启动后约 0.5 秒内第二次续租的来源（例如缓存 ACTIVE 后定时器立即触发、页面状态通知又触发一次、或主进程与后端各发一次），改为**启动只续租一次**，之后 60 秒一次。加测试：模拟已缓存 ACTIVE 启动，前 5 秒内续租请求恰好 1 次。不得因此推迟首次续租。
3. 使用中被停用约 1 分钟后才锁定，是心跳间隔造成的，**属于设计，不改**。

# 英雄梯度与构建推荐设计

日期：2026-08-11

## 目标

新增一个不依赖英雄联盟客户端登录的一级“英雄”工作区，只展示韩服统计，首期完成“单/双排”和“海克斯大乱斗”列表与详情；“斗魂竞技场”保留稳定入口和待实现状态。

用户可以按段位、位置和英雄搜索快速找到梯度、符文、召唤师技能、技能加点、出装与海克斯推荐。数据不足或上游不可用时明确降级，不以本机账号对局或推测值替代韩服聚合数据。

## 信息架构

- 一级侧栏：总览 / 英雄 / 对局 / 收藏。
- “英雄”位于“总览”和“对局”之间；页面标题为“英雄”，副标题为“韩服梯度、符文与构建推荐”。
- 页面顶部第一行是数据说明、段位选择和刷新操作。
- 第二行是模式页签：单/双排 / 海克斯大乱斗 / 斗魂竞技场。
- 详情在同一工作区内钻取；返回列表时恢复模式、段位、位置、搜索词和滚动位置。

## 筛选与搜索

单/双排支持全部、上单、打野、中单、下路、辅助，并带统一线性位置图标。默认位置保存在本地设置中。

段位沿用 OP.GG 当前枚举并显式包含最强王者：全部段位、最强王者、傲世宗师、超凡大师以上、超凡大师、钻石以上、钻石、翡翠以上、翡翠、铂金以上、铂金、黄金以上、黄金、白银、青铜、黑铁。

搜索输入位于梯度列表顶部，支持：

- 中文英雄名与称号；
- 英文名、英文单词前缀和首字母缩写；
- 中文全拼和拼音首字母；
- 维护在别名表中的常见外号；
- 忽略大小写、空格、连字符、点号和全半角差异。

## 单/双排列表

列表使用紧凑表格，不复制 OP.GG 品牌：排名、英雄、梯度、位置、胜率、选用率、禁用率。移除“对线劣势英雄”。

“全部”位置会把同一英雄的主位置作为主要行，并保留其它可用位置标签；选择具体位置后只显示该位置并按 OP.GG 的位置排名排序。点击任意行进入对应英雄和位置的详情。

## 单/双排详情

详情头部展示英雄头像、中文名/英文名、当前位置、版本、梯度、胜率、选用率与禁用率。正文按任务顺序排列：

1. 推荐符文；
2. 召唤师技能；
3. 技能加点；
4. 出门装与鞋子；
5. 核心装备路线；
6. 第四、第五、第六件装备。

符文、装备、技能和召唤师技能使用统一的 `RecommendationSection`、`AssetSequence`、`MetricPair` 组件模型。原有对局页仍展示单场事实，新页面展示统计推荐；二者共享图标序列、技能序列和数据指标的视觉语汇，但不混用数据含义。

## 海克斯大乱斗列表

宽窗口使用左右两栏：左侧是按梯度排名的英雄列表，右侧是全部海克斯目录；窄窗口改为上下排列，英雄列表先展示。

英雄区只有梯度视图，不保留 OP.GG 的“英雄/段位”切换。海克斯区提供全部、银、黄金、棱镜筛选和名称搜索。每张海克斯条目展示图标、等级、名称、清理后的中文描述、统计热度/表现以及适配英雄头像。

## 海克斯大乱斗详情

详情先展示该英雄最适合的海克斯，再展示召唤师技能、技能加点、出门装、鞋子和核心装备。详情使用与单/双排相同的通用构建组件；海克斯推荐使用独立的紧凑排行组件。

## 数据流

渲染进程只请求本机 Go 服务：

- `GET /api/champions/catalog`
- `GET /api/champions/rankings?mode=ranked&tier=...&position=...`
- `GET /api/champions/rankings?mode=aram-mayhem`
- `GET /api/champions/augments`
- `GET /api/champions/detail?mode=...&champion=...&position=...&tier=...`
- `GET /api/champion-asset?...`

Go 服务使用固定 HTTPS 主机和固定路径模板访问 OP.GG、Data Dragon 与 OP.GG 静态资源域。任何 URL、主机或任意文件路径都不由渲染进程直接提供。请求限制重定向、响应体大小和超时，并返回规范化 JSON。

单/双排梯度来自 OP.GG `KR` 统计接口；英雄目录与技能说明来自版本化 Data Dragon；详情和海克斯大乱斗来自带中文 locale 的 OP.GG 公开服务端页面数据。页面明确显示来源、区域、版本和本次读取时间。

## 联网与缓存

- 每次进入页面或手动刷新都会联网获取当前数据。
- 应用不建立全量图片库；列表和详情图片使用原生 `loading=lazy` 按需请求。
- 静态资源响应允许 Electron/Chromium 使用正常 HTTP 缓存，不额外复制所有图标。
- Go 进程只做短时请求合并，避免同一页面同时重复请求；不把旧统计冒充最新统计。
- 断网或 OP.GG 不可用时显示可重试错误，不要求启动客户端。

## 状态与可访问性

- 初次加载使用与表格行一致的骨架，不使用居中旋转器。
- 空搜索结果保留当前筛选摘要并提供清除操作。
- 上游错误区分网络失败、数据结构变化和无样本；所有状态可重试。
- 页签、位置筛选、表格行和返回操作可键盘使用；焦点环沿用全局样式。
- 数据表在窄窗口采用必要的横向滚动，搜索和页签允许换行；不压缩点击区域。
- 只用 160–220ms 状态过渡，并支持 `prefers-reduced-motion`。

## 验证

- Go provider 单元测试覆盖参数白名单、韩服路径、超时、响应上限、无效数据和解析器。
- 前端脚本语法检查与 HTML/CSS 结构测试。
- 运行 `go test ./...`、`go vet ./...`、Node 测试与 JavaScript 语法检查。
- 在 1280、900、620、380 宽度检查明暗主题、键盘焦点、横向溢出和详情返回状态。

## 已知边界

OP.GG 娱乐模式页面本身不提供段位筛选，因此顶部段位选择只影响支持段位样本的单/双排；切换到海克斯大乱斗时保留选择但标明该模式使用 OP.GG 当前娱乐模式样本。斗魂竞技场本期只建立入口，不填充虚构数据。

# WORKLIST-R217：战绩关键词标签只剩 4 个能用——改为复现 OP.GG 的“输赢 + 前后段走势 + 结尾档位”规则，用每分钟曲线，再用新样本验证

诊断人：Claude（R216 留出集一次性评估；在 R211 的 260 局训练数据上拆解 OP.GG 关键词的生成方式）。执行人：GPT。日期：2026-10-05。基线：R216 工作区。构建 / 发布按当前暂停指示。

**前提**：R216 P4 的收尾照常做。评分切到 v2.1，10 个关键词先关闭，只保留势不可挡、坚韧、不走运、挣扎。本单完成并通过验证后，才重新打开达标的关键词。

用户提议把样本扩大到 1000 个账号。**本单不这样做**，理由见“为什么不靠扩大样本”。

---

## 诊断

### 1. 留出集结果

R216 的关键词方案在 300 局新样本（2970 人）上整体准确率 36%。14 个关键词里只有 4 个的准确率 ≥ 40%。最离谱的是“慢热”：预测了 336 次，实际只出现 7 次。

### 2. OP.GG 的关键词其实是一张查表（Claude 用 260 局、2600 人实算）

OP.GG 每个人的数据里有 `op_score_timeline_analysis: {left, right, last}`：
- `left`、`right`：UP / DOWN。
- `last`：POOR / FAIR / GOOD / EXCELLENT。

**只用（输赢, 是否本队最高, left, right, last）五项查表，就能 96.2% 复现 OP.GG 的关键词**，共 42 种组合。主要几行：

| 输赢 | left | right | last | 关键词 |
|---|---|---|---|---|
| 负 | DOWN | DOWN | FAIR | 挣扎（480/480） |
| 胜 | UP | UP | GOOD | 势不可挡（另有 100 人是领袖） |
| 负 | UP | DOWN | FAIR | 下坡路（194/194） |
| 胜 | DOWN | UP | GOOD | 大器晚成（157/157） |
| 胜 | DOWN | DOWN | GOOD / EXCELLENT | 坚韧 |
| 负 | DOWN | DOWN | GOOD | 不屈之志 |
| 胜 | UP | UP | FAIR | 胜者 |
| 负 | UP | UP | * | 不走运（本队最高且 GOOD 时为竭尽全力） |

完整表格由 GPT 从数据重新生成（见 P1），不要照抄上表。剩下约 4% 的歧义几乎全在“势不可挡 / 领袖”之间，需要找出区分它们的那一个因素。

### 3. R216 的做法和 OP.GG 不一样

- R216 用的是自定义特征（前 1/3 均值、后 1/3 均值、Δ、最低点、振幅、拐点次数）加阈值链，和 OP.GG 的结构对不上。再怎么调阈值也只是在逼近一个形状不同的规则。
- 检查点：R216 是每 5 分钟一个（`match_tags.go` 的 `interval := 300`），**OP.GG 是每分钟一个**（`op_score_timeline` 的 `second` 为 60、120……），前后段走势判定的分辨率差很多。

### 4. left / right / last 不是简单的首尾差

在 OP.GG **自己的**曲线上试了几种直观定义：
- 中点切两半看首尾差：left 80%、right 74%。
- 前 40% / 后 60% 各做最小二乘斜率：left 84%、right 78%。
- `last` 和最终 OP Score 的数值区间大量重叠：FAIR 0～9.47，GOOD 1.6～10。所以它不是“最终分档位”，可能是最后一段相对前面的变化。

这一步要先研究清楚。

### 为什么不靠扩大样本

- **现有样本已经够研究规则**：R211 的 260 局加 R216 的 300 局，共 560 局、5,600 人。常见关键词每个都有几百例。规则错了，加多少样本都学不对。
- **罕见关键词本身就罕见**：竭尽全力 10 例、慢热 9 例、奉献 3 例，在 OP.GG 上的出现率也只有 0.1%～0.4%，扩大样本对用户看到的效果影响很小。
- **代价**：1000 个账号约 2 万局，Riot 个人 Key 要跑十几个小时，还要从 OP.GG 抓 2 万局页面，很可能被限流或封。
- **结论**：先把规则对准，再采一批 200 局的新留出集验证就够了。

## P1　从 OP.GG 自己的曲线反推 left / right / last 和查表（只用训练数据）

**训练数据**：R211 的 260 局 + R216 的 300 局。R216 留出集已对评分和 R216 关键词各评估过一次，本单允许把它当训练数据用，最终验证换 P3 的新样本。

1. **查表**：
   - 从训练数据生成（输赢, 本队最高, left, right, last）→ 关键词的完整表格，每格记出现次数和多数关键词占比。
   - 找出“势不可挡 / 领袖”的区分因素。可尝试：全场名次是否第 1、OP Score 是否满分、胜方第二名分差、`op_score_rank`。
   - 目标：查表在训练数据上 ≥ 97%。
2. **用 OP.GG 自己的 `op_score_timeline` 反推 left / right / last**：
   - 只用可解释的规则：分段位置（按时间或按点数）、斜率或差值、阈值、与全场或本队的比较。不得使用黑盒模型。
   - 候选定义要覆盖：分段点在 1/3 / 中点 / 2/3 / 固定分钟；用首尾差、最小二乘斜率或段内最值；`last` 可能是“最后一段的变化幅度”“结尾相对全局最值”“结尾相对同队”等。逐个报告准确率。
   - **目标：三项在 OP.GG 自己的曲线上各 ≥ 95%。** 达不到就报告最好的定义和误差集中在哪类曲线，停下来等用户。
3. 输出 `docs/history/reports/r217/opgg-rule-study.json`：每个候选定义的准确率，以及最终选中的定义。

这一步不涉及我们的评分。它回答的是：OP.GG 的规则能不能被准确复现。

## P2　用我们的每分钟曲线套用 P1 规则

1. `match_tags.go` 的检查点改为**每 60 秒一个**，与 OP.GG 一致；大乱斗 / 海斗按 OP.GG 实际间隔核对后再定，账本写明。每个检查点用 v2.1 评分、只用截至该时刻的累计数据，视野仍不进时间线。
2. 先算 left / right / last 再查表，替换 R216 的阈值链。
3. 在训练数据上报告：
   - **我们的曲线**推出的 left / right / last 各自与 OP.GG 的一致率。
   - 最终关键词的逐项 precision / recall。
   - 我们的曲线与 OP.GG 曲线的逐点相关度（中位数）。
4. 如果走势一致率明显低于关键词需要的水平，允许针对**时间线评分**做有限调整，在训练数据上用按账号分组的交叉验证选择：
   - 时间线里缺的维度如何处理。
   - 伤害取自帧里的 `damageStats`。
   - 早期分钟数据过少时的平滑。

   不得为了关键词改动结算评分（v2.1 已冻结上线）。
5. 冻结：查表、走势规则、时间线评分参数写进 `docs/history/reports/r217/keyword-candidate.json`，记 SHA-256。冻结后不改。

## P3　新留出集与一次性评估（Claude 运行）

1. **采集**：按 R216 的选号方式再选 **16 个新 KR 账号**，高分段 / 普通各半，与 R211、R216 的所有源账号和对局都不重叠。
   - **目标 200 局**，每个账号最多 15 局。
   - 只采集，不读结果；冻结 manifest 后停下。
2. **评估脚本** `scripts/r217-evaluate-keywords.py`，仿照 R216：
   - 校验 hash，写独占标记，只运行一次。
   - 用上线的 Go 函数算关键词。
   - 报告：逐关键词 precision / recall，left / right / last 一致率，整体准确率；高分段 / 普通分组各一套。
   - GPT 不运行，由 Claude 运行。
3. **上线规则**（评估前固定）：
   - precision ≥ 50% 的关键词打开，低于的保持关闭。比 R216 的 40% 更严，因为关键词显示在每张战绩卡上，错了用户一眼能看出来。
   - 已经打开的 4 个关键词同样按新结果重新判定。

## 测试

- **Go**：
  - 每分钟检查点数量与对局时长一致。
  - 查表覆盖训练数据里出现的全部组合；没见过的组合不出关键词。
  - left / right / last 规则用构造曲线各覆盖一个 UP / DOWN 和四档 `last`。
  - 同一 gameId 第二次不重复请求时间线（沿用 R216 持久化）。
- **持久化**：关键词模型版本 +1，旧的 R216 关键词结果不得复用。
- **Node**：被关闭的关键词不渲染；打开的使用站内用词和既有色板。

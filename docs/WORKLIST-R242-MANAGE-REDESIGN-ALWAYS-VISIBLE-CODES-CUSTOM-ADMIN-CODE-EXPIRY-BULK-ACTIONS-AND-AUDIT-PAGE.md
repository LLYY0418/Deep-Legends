## P1　数据结构与加密保存注册码（会话 B）

现在服务端**只保存注册码的 SHA-256 摘要**，所以无法再次显示。要"随时可见"，必须可逆地保存注册码本身。方案如下：

1. **新增 Secret `CODE_ENCRYPTION_KEY`**：32 字节随机数，base64url 编码，由用户生成并上传。用 AES-256-GCM 加密注册码，每个码一个随机 12 字节 IV，附加认证数据（AAD）用 `license_id`，防止把密文挪到别的行。查找仍用 `code_digest`，激活流程不变。
2. **新增迁移 `migrations/0002_*.sql`**，`licenses` 表加列：
   - `code_cipher TEXT`：IV + 密文，base64url；旧数据为 NULL。
   - `expiry_mode TEXT NOT NULL DEFAULT 'none'`，取值 `none`（永久）、`from_activation`（首次激活起算）、`from_creation`（生成时起算）、`fixed_date`（指定到期日）。
   - `duration_days INTEGER`：有效天数，`none`、`fixed_date` 为 NULL。
   - `expires_at INTEGER`：到期时间（Unix 秒）。`from_activation` 在首次激活时写入；未激活时为 NULL。
   - 为 `expires_at` 加索引，用于"7 天内到期""已过期"筛选。
3. **旧码**：`code_cipher` 为 NULL 的码，列表和详情显示"旧版本生成，无法显示"，并提供"重置为新码"。不得尝试反推。
4. **缺少 `CODE_ENCRYPTION_KEY` 或格式不对时**：
   - 生成、重置、自定义管理员码都返回 503，并给出明确提示，避免生成出永远看不到的码。
   - 列表照常显示，注册码一栏显示"无法解密"。
   - 激活、续租不受影响。
5. **安全要求**：
   - 管理接口返回明文注册码的响应必须带 `Cache-Control: no-store`。
   - 日志、事件、审计详情里**都不写注册码明文**。
   - 只有通过 Cloudflare Access 的管理员能拿到明文，客户端接口不返回明文。
   - 在 `docs/` 中写清风险：数据库和这个 Secret 同时泄露，注册码就会泄露。这是"随时可见"的代价，由用户确认接受。

## P3　管理员码可以自己设置（会话 B）

1. 生成管理员码时选择"自己设置"或"随机生成"，默认"自己设置"。
2. 自定义码的规则与客户端输入规则完全一致，**客户端不用改**：
   - 20 位，可用数字和除 I、L、O、U 以外的字母。
   - 输入时自动大写，短横线和空格自动忽略；O 按 0 处理，I、L 按 1 处理（与现有 `normalizeCode` 相同）。
   - 界面上实时显示规范化后的结果。
3. **服务端校验**（前端同时提示，以服务端为准）：
   - 格式正确。
   - 不与任何现有码重复（按摘要判断，包括已停用的码）。
   - 不易猜到：至少 8 种不同字符；同一字符最多出现 5 次；不能包含 6 位以上的连续递增或递减序列（例如 `123456`、`ABCDEF`）。
   - 不满足时返回具体原因，在输入框下方显示。
4. 已有管理员码可以在详情抽屉里"修改注册码"：可以自己设置新码，也可以随机生成。修改后旧码立即失效，已登录的设备按现有"重置"规则处理（下次续租显示"注册码已在其他设备使用或已被重置"，需要输入新码）。需要二次确认并输入 `ADMIN`。
5. 普通码**不提供**自定义，只能随机生成（避免批量码可被猜测）。
6. 审计记录"自定义管理员码"或"修改管理员码"，**不记录码本身**。

## P4　普通码有效期（会话 B）

1. **生成时选择**：
   - 有效期：永久、30 天、90 天、180 天、365 天、指定到期日。默认永久。
   - 开始计时：首次激活时（默认）、生成时。只有选择天数时才显示。
2. **到期计算**：
   - 首次激活起算：`expires_at = 首次激活时刻 + 天数×86400`，在第一次激活成功时写入。
   - 生成时起算：生成时直接写入。
   - 指定到期日：按北京时间当天 23:59:59 计算。
3. **调整有效期**（详情抽屉和批量操作）：
   - +30 天、+90 天：从 `max(现在, 原到期时间)` 往后加。还没开始计时的"首次激活起算"码，直接增加 `duration_days`。
   - 设置到期日、改为永久。
   - 每次调整写审计，内容为调整前后的到期时间。
4. **服务端强制**：
   - 激活或续租时，如果码已过期，返回新的错误码 **`EXPIRED`**（P6）。
   - 有效期内，租约到期时间取 `min(签发时间 + 900 秒, 注册码到期时间)`，保证到期后最多 15 分钟内客户端锁定（实际是到期时立即锁定）。
   - 管理员码也可以设置有效期，规则相同。
5. 已过期的码在列表中状态显示"已过期"。续期后客户端需要重新输入注册码，规则同"停用后启用"。

## P5　批量操作与导出（会话 B）

1. 勾选后出现批量操作栏，操作有：续期（+30/+90/设置到期日）、复制注册码（每行一个）、启用、停用。支持当前页全选，单次最多 100 个。
2. 新增接口 `POST /admin/api/licenses/batch`，参数为 `{action, ids, ...}`。每个码独立执行（停用/启用仍走各自的 LicenseDO），返回每个码的结果。部分失败时，在提示中写清"成功 N 个，失败 M 个"，失败的行保持勾选。
3. "导出 CSV"导出**当前筛选条件下的全部结果**（不只当前页），列：注册码、类型、状态、有效期、到期日、设备、最后在线、批次、备注、创建时间、首次激活时间。用 UTF-8 BOM，保证 Excel 打开中文不乱码。导出和批量复制都写审计（数量和筛选条件，不写码）。

## P7　运维优化（会话 B，上线前完成）

1. **续租时减少 D1 写入**：续租成功时，只有在设备变化、状态变化，或距离上次写入超过 5 分钟时，才更新 `licenses` 摘要。LicenseDO 内的计数器照常每次写入（防重放需要）。列表的"最后在线"因此最多有 5 分钟误差，"当前在线"按租约判断不受影响。
2. **限制未绑定设备记录**：每个注册码的 LicenseDO 中，`bound=0` 且 `last_seen` 早于 1 小时的设备记录，超过 200 条时删除最旧的。只能删除超过时间戳容差（现在是 300 秒）的记录，因为激活请求超过容差会被 `TIMESTAMP_INVALID` 拒绝，删除后不会被重放利用。写测试证明：删除后重放旧激活请求仍被拒绝。
3. 这两项都要有测试，并在账本中写出数据库写入次数的前后对比（模拟 100 次续租）。

## 验收标准

- 管理页按设计稿重做，列表、详情抽屉、生成弹窗、操作日志四个界面齐全。手机宽度下可用。
- 所有用新版本生成的注册码，在列表、详情、CSV 中都能随时看到和复制；旧测试码显示"无法显示"。
- 管理员码可以自己设置，弱码和重复码被拒绝。
- 普通码可以设置有效期，到期后客户端显示"注册码已过期"，续期并重新输入后恢复。
- 批量续期、启用、停用、复制、导出可用，都写入审计（不含注册码明文）。
- 续租时 D1 写入明显减少；未绑定设备记录有上限，且不能被重放利用。
- 两个仓库的指定检查全部实跑通过，并出新的 STAGING 包。

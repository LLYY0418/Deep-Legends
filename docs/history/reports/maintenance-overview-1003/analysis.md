## 原因与修复

旧 `applyOverviewSkinMedia` 仅查 `a.allSkins`。该数组在完整收藏刷新成功时建立；生涯页另有独立的公开目录缓存，总览没有使用它。总览虽已有正确皮肤 ID，首次无法取得客户端原画/动画路径，只能走普通图片回退。日志中的 GTImg 网络失败及本地 splash 400 使回退也未能可靠显示。进入收藏后建立目录，再次总览便能取得本地原画。这是明确的目录生命周期依赖；日志中的 ID 已存在，不能将本例归因于玩家背景设置为空。

修复首次总览并行读取公开目录和当前背景链：复用生涯的客户端范围目录缓存，读取当前 profile 与实际 backdrop，保留客户端给出的真实路径；使用实际目录的 centered 原画与匹配构图的动画。目录失败或超时时，已读到的直接背景路径仍可显示；未知自动背景不推测皮肤 ID。目录与背景共享最多 3 秒的预算，并与战绩读取并行；分页不增加背景请求。状态查询用非阻塞缓存读取，避免等待目录网络锁。身份状态没有可用图片时保留当前总览背景，同一皮肤暂缺 poster 时也不清掉已有原画；新皮肤的有效路径仍正常替换。

维护页删除旧开关、POST `/api/rig/settings-sync`、keepGameSettings 状态及结算 5 秒同步调度/写入。镜头控件进入右侧 `rig-actions`，四个选项、立即保存、失败回滚保持。旧 `game-settings-sync.json` 的 `cameraMode` 继续读取，`enabled` 被忽略，下一次保存移除该字段；实际自动写入声明同步删除旧功能。设置观察继续只读记录，镜头应用保留自己的阶段与安全验证。

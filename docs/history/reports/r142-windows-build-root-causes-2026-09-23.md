# R142 Windows 构建排障复盘

本轮输入：用户 2026-09-23 提交的完整日志，Go 根模块与 installer 模块通过，前端 692 项中 677 通过、15 失败。

## 根因

Windows Git 自动转换 CRLF，而仓库若干源码契约测试使用精确 LF 字符串、LF 函数结尾和定长正则提取源码。包括 champions、R113、R114、R116-E、R90。CSS 定长正则也会因为多出的 CR 字节超过长度限制。此前仅约束 Go 与 manifest，遗漏 JavaScript、CSS 及其他构建文本。测试失败不能据此判断对应 UI 功能损坏。

此前报错分别来自：PowerShell 5.1 编码读取、管理员终端 Node 版本、symlink 权限、Go 模块网络下载、Windows 时间戳重复引发缓存竞态/LRU 顺序、依赖安装晚于测试、manifest 的 CRLF 字节与 syso 不一致。逐项补丁缺少完整 Windows 克隆预检，导致用户重复长时间运行。

## 本轮修复

- Git 文本文件统一 LF；二进制保持自动识别。
- Windows 主构建入口在任何测试及指纹计算前统一源码行尾；覆盖已有 checkout，不依赖重新克隆。
- 字节替换保留 UTF-8 BOM；仅处理指定源码目录及文本扩展名，跳过符号链接、依赖、产物、payload 和本地 key 文件。
- 去除 public 包装脚本中局部重复处理。
- CI 校验及上传改为实际 public 校验文件名 SHA256SUMS-public.txt。

## 验证方式与边界

在 /private/tmp 的隔离源码副本转换构建文本为 CRLF，复现用户全部 15 项失败，另暴露 3 项同类失败。运行统一处理后，对比所有被跟踪构建源码，字节完全一致（含 35 个二进制文件），源码指纹与本地一致。另有 BOM、二进制、依赖、产物、符号链接和幂等性回归测试。

验证结果：CRLF 副本修正后，完整前端与桌面测试 954 项，953 通过、1 跳过、0 失败；本地前端单独运行 692/692 通过。源码指纹两端一致为 `803df705101d`。

本机为 macOS。CRLF 模拟可以验证本轮根因，不能代替真实 Windows 的最终 NSIS 打包、运行自检及 public 发布验收；R142 在收到这些产物前仍未完成。

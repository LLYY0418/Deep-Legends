## 在线升级后 Riot API Key 没了（绝活哥显示"未配置 Riot Key"）

### 现象

用户截图：选人阶段符文页「绝活哥」显示"未配置 Riot Key · 本次后台读取未完成，稍后刷新时会自动重试。· 去设置"。

### 证据

日志 `lol-loot-diagnostics-1003-2002.jsonl` / `-2044.jsonl` 的 `app_start`：

| 时间 (UTC) | 版本 | 构建 | `riot_key` |
|---|---|---|---|
| 08:04～10:35（4 次启动） | 0.12.60 | `530db182f4c1` | **true** |
| 10:54 | 0.12.60 → 0.12.63 在线升级 | | |
| 10:55、11:29、12:16 | 0.12.63 | `c21482dba3c7` | **false** |

### 根因（源码已核对）

1. `backend/riot_api.go`：Key 只有两个来源：环境变量 `RIOT_API_KEY`，或构建时注入的 `riotAPIKeyCipher` / `riotAPIKey`。**没有用户在软件里填写、保存的来源。**
2. 用户之前装的 0.12.60（`530db182`）是本地 **private** 构建，构建脚本从 `riot_key.local.txt` 注入了 Key。
3. GitHub 上发布的都是 **public** 构建，按设计不含 Key（`verify-embedded-riot-key.cjs` 会拦截含 Key 的 public 包；GitHub Release 匿名可下载，把 Key 放进去等于公开）。
4. 在线升级用 public 安装包覆盖了 private 版本，Key 就没了。以后每次在线升级都会这样。
5. 页面上的"稍后刷新时会自动重试"和"去设置"都不对：没有 Key，重试不会成功；设置页也没有填 Key 的地方。

### 修改

1. **设置页加 Riot API Key 输入**：放在「设置 → 隐私与能力」。一个密码样式的输入框（默认遮挡，可点眼睛查看），按钮「保存」「清除」，旁边状态 `已配置` / `未配置` / `无效`。不加其他说明文字。
2. **本地加密保存**：用 Windows DPAPI（`CryptProtectData`，当前用户范围）加密后存进软件数据目录，不写日志、不进诊断导出、不上传。非 Windows 环境（开发用）存在同目录并限制文件权限 0600。
3. **读取优先级**：环境变量 `RIOT_API_KEY` → 用户保存的 Key → 构建时内置的 Key。`riotKey()` 改为按这个顺序读取。保存或清除后**立即生效**，不用重启。
4. **保存时验证**：用这个 Key 请求一次韩服的轻量接口（例如 `GET https://kr.api.riotgames.com/lol/status/v4/platform-data`）。200 → `已配置`；401/403 → `无效`，并且**不保存**；网络错误 → 仍然保存，状态显示 `已配置`（下次请求时再判断）。Key 用到一半返回 401/403 时（例如开发者 Key 24 小时过期），状态改为 `无效`，绝活哥那里的提示改为"Riot Key 无效"。
5. **升级时把 private 版本里的 Key 带过去**：当前运行的是内置了 Key 的版本，并且用户还没有保存过 Key 时，在启动安装程序之前（`update_data_migration stage=pre_install` 同一位置），把内置 Key 按第 2 条加密保存一份。这样从 private 版本在线升级到 public 版本后，Key 仍然可用。只做一次，不覆盖用户自己保存的 Key。
6. **提示文字修正**：没有 Key 时，绝活哥空状态只显示"未配置 Riot Key"和「去设置」（跳到第 1 条的输入框并聚焦），去掉"本次后台读取未完成，稍后刷新时会自动重试"。其他用到 `errRiotKeyMissing` 的地方同样处理。
7. **诊断**：`app_start` 的 `riot_key` 改为 `riot_key_source`：`env` / `user` / `embedded` / `none`。另记 `riot_key_saved`（`result=ok/invalid/network_error`）、`riot_key_migrated`（升级前迁移，`result=ok/skipped_exists/skipped_no_embedded`）。都不记 Key 本身或其任何片段、哈希。

### 测试

Go：
1. 只设环境变量 → 用环境变量；只有用户保存的 → 用用户的；只有内置的 → 用内置的；三者都有 → 环境变量优先。
2. 保存：验证接口返回 200 → 保存并生效；返回 401 → 不保存，状态 `invalid`；网络错误 → 保存，状态 `已配置`。
3. 清除 → `riotKey()` 回到内置或空，绝活哥显示"未配置 Riot Key"。
4. 升级前迁移：有内置 Key、没有用户 Key → 加密保存，`riot_key_migrated result=ok`；已有用户 Key → 不覆盖，`skipped_exists`；public 版本 → `skipped_no_embedded`。
5. 诊断和导出的日志里搜不到 Key 明文、`RGAPI-` 前缀和 DPAPI 密文。
6. 运行中请求返回 401 → 状态变 `无效`。

Node：
7. 设置页有输入框、保存、清除和状态；输入默认遮挡。
8. 绝活哥 Key 缺失时只有"未配置 Riot Key"+「去设置」，没有"稍后刷新时会自动重试"；点「去设置」跳到输入框。

变异：内置 Key 优先于用户 Key → 测试 1 FAIL；401 仍保存 → 测试 2 FAIL；日志里出现 Key → 测试 5 FAIL。

## P8　安装进度慢、容易卡在一个数值不动

### 证据

| 时间 (UTC) | 事件 |
|---|---|
| 14:21:45.99 | 用户点「立即升级」（`/api/update/apply` 用时 1.4 秒） |
| 14:21:47.7 | 旧版 0.12.63 退出（`champselect_delivery reason=connection-ended`） |
| 14:22:37.9 | 新版 0.12.65 启动；**`update_install_timing result=invalid`** |

安装用了约 **50 秒**（R201 之前是 73 秒）。用户截图：安装窗口停在 **92%「正在写入程序文件…」** 很久不动，感觉比正常安装还慢。

问题：R201 P1-5 的安装计时文件在真机上读出来是 `invalid`，所以各阶段耗时没有记录，无法确定慢在哪一段。

### 修改

1. **先修计时**：查清 `update-install-timing.json` 为什么是 `invalid`（这次是 0.12.63 → 0.12.65：旧版没有传 PID，走的是 R201 的兼容路径；可能是兼容路径没写 `parent_exited`，或时间点不完整就被判无效）。改为：缺字段的阶段记 `null`，其余照常记录，不再整份判 `invalid`；`invalid` 时同时记原因（`parse_error` / `missing_fields` / `clock_skew` 等）。
2. **补一个阶段**：electron-builder 的 NSIS 在覆盖安装时会先静默运行旧版本的卸载程序、删除旧文件，然后才解压新文件。在这一步前后加时间点 `uninstall_old_start` / `uninstall_old_done`。这一步很可能就是"卡在一个数值不动"的原因（这段时间没有解压和复制字节，进度只靠时间兜底慢慢涨）。
3. **进度条按阶段走，不再在一个值上停很久**：等待旧程序退出（0–5%）→ 移除旧版本（5–25%）→ 解压（25–60%）→ 写入（60–95%）→ 收尾（95–100%）。每个阶段内按实际字节或文件数前进；没有字节可算的阶段，在该阶段的区间内按时间平滑前进。阶段文字对应显示（"正在移除旧版本…"等）。
4. **提速**：拿到第 1 条的计时后，如果"移除旧版本"或"解压"占大头，在账本里给出数据和选项：
   - 升级时不跑旧版卸载程序，改为直接覆盖、再删除新版本里已不存在的旧文件；
   - NSIS 压缩方式从 LZMA 固实压缩改为解压更快的方式（安装包会变大，但下载已经很快）。

   选哪个由数据决定，账本写明前后对比。不改手动安装的流程。

测试：计时文件缺一个阶段 → 其余阶段照常记录，缺的为 `null`；各阶段进度区间不倒退、不越界；"移除旧版本"阶段持续 20 秒时进度在 5–25% 之间平滑前进。

## P10　对局页战绩加载

### 结论

**没有比以前慢。** 10 个人的战绩：

| 版本 | `live_load_cost matches_ms`（10 人） |
|---|---|
| 0.12.60 / 0.12.63（R202 之前） | 3.6–9.5 秒，多数 6–8 秒 |
| 0.12.65（本日志正式海斗） | 选人 8.5 秒；进游戏 4.5–7.0 秒 |

R202 P5 的服务器按队列筛选在 2400 上可用：`queue_filtered=true pages_read=1`，大多数玩家一次拿够 10 局（`stop_reason=enough`）。

### 可以改进的地方

1. **自定义 / 练习模式不翻页**：queue 3140 这类自定义对局，服务器筛选不可用，回退时翻满 4 页（120 局）仍然一局都匹配不到（`page_limit shown_count=0`），白白多花 2–5 秒。自定义、练习、人机这类队列：只读 1 页，不往后翻。
2. **SGP 已筛够 10 局时不再读 LCU 30 局**：除了本人（R180/R181 需要本人最新一局），其他玩家在 SGP 按队列筛选已经拿到 10 局时，跳过 LCU 那一路 30 局读取，减少并发占用。
3. **逐个玩家显示**：前端在拿到每个玩家的战绩后就更新那张卡片，不等 10 个人都完成（如果现在已经是逐个显示，账本写明即可）。
4. `live_load_cost` 增加 `sgp_ms`、`lcu_ms`、`slowest_player_ms`，方便下次比较。
5. 目标：10 人选人阶段战绩全部显示 ≤ 5 秒（网络正常时）。

测试（Go）：queue 3140 回退 → `pages_read=1`；非本人玩家 SGP 筛够 10 局 → 不发 LCU 30 局请求；本人仍然读。

## 已确认的原因与改动

| 用户现象 | 原因与修复 |
|---|---|
| 国服、韩服总览头像、英雄、装备、符文都不显示 | `prepareImages` 把无 `src`、尚待队列接纳的图片当成失败。浏览器此时 `complete=true/naturalWidth=0`，隐藏后又无法触发可视区加载。改为仅判断实际存在 `src` 的图片，加载成功及重新接纳时恢复可见。英雄页同类代码一并修复。 |
| 首次总览段位慢 | 日志 seq 632：account 0–890ms，matchIDs 890–1463ms，ranks 1463–2049ms。段位与熟练度原先等待 match IDs 返回后才开始；现在账号解析完成即与列表并发读取。保留既有详情渐进发布与历史异步更新。 |
| 生涯背景/皮肤首次缺失 | 日志多次 `skin_count=0`，随后可读到 2121；当前背景 ID 实际为 0。未设置背景时，原下拉视觉首项与空的 draft.hero 不一致，导致过滤后始终无皮肤。现在初始化真实英雄选项、支持背景原画后备地址，不自动写入。共享读取不再随切页取消而被污染，取消结果不作为目录负缓存。 |
| 生涯首次整屏等待 | 客户端连接后后端与前端预加载，账号隔离的内存快照复用；没有快照时先显示布局。把诊断探测移出首屏等待。用户写入前后废弃旧缓存及旧 flight，防止迟到读取覆盖新状态。首次无缓存仍受客户端/网络速度影响，未承诺零等待。 |
| 选择未拥有头像/旗帜出错 | seq 633/634、656–658、683 的头像 PUT 返回 401 RPC_ERROR；旗帜请求后回读没有变成目标。增加只读短暂回查，仍未生效时保留弹窗并给出明确说明。不重试写请求，不伪报成功，也没有证据证明当前客户端允许装备这些未拥有物品。 |
| 头像选择器重复加载 | 数字 ID 的公开头像图片加入有容量上限的磁盘缓存，拒绝缓存非图片错误响应；重启复用。前端成功 URL 十分钟内优先复用浏览器缓存，不排在两路冷请求之后。 |
| 旗帜太小、重复文案、缺搜索 | 预览高度 96→180px；去掉每张卡片的“点击更改”，保留必要国服专属说明；加入名称、拼音、编号搜索。用户“价格搜索框”按“加个搜索框”理解，未编造价格数据。 |
| 职业账号段位/时间慢或缺失 | 原先缺失账号依赖一分钟一个的 Riot 补全。启动时启动六路并发公开页面读取，完整检查固定 33 人/53 账号，检查后整批更新。严格验证 KR + 精确 Riot ID，只读取当前单双排区域，不取最高/历史段位。所有账号保留检查时间，来源提供时显示真实更新时间。 |
| 无段位账号折叠与 72h | 只有明确“未定级”的来源结果缓存 72h，有段位 15min，失败短暂退避并保留旧段位；结果持久化。未定级与暂不可用账号默认折叠，展开仍包含全部 53 个，失败不会被当成未定级。 |

缓存白名单也已补齐：最初跨重启回归发现写入被旧白名单跳过，修正后磁盘复用测试通过。目录失败时替换旧 seed 记录，避免重复追加。新账号检查不占用 Riot API 请求配额。

# R113：真实对局日志、页签串页、阵营播报与对局预加载

日期：2026-09-19。输入：`lol-loot-diagnostics-0919-1756.jsonl` 和同日 15:51、16:25 的三张截图。本轮不构建、不打包，不继续投入未拥有头像/旗帜的切换。

## 日志证据与结论

- 读取了 7,544 条有效 JSON 记录（另有 1 行无法按 JSON 解析），覆盖 UTC 07:33:54–09:56:37。没有发现已记录的 HTTP 429 或 403，不能把本次所有慢请求归因于 Riot Key 限流。
- 阵营播报记录了 171 次 armed、134 次失败，其中 110 次 `conversation-unavailable`、24 次 `session-read-failed`；15 次成功。原实现会因连续选人事件反复重试，聊天 ID 校验又不接受合法的 `room@conference.domain` 格式。失败记录本身不能证明这 110 次全部由 ID 校验造成，初始会话尚未就绪也会产生同一原因。
- SGP 有 69 次 HTTP 200、1 次 HTTP 503：`log_seq=151`，耗时 1,037 ms。当前对局接口有一次 502：`log_seq=687`。这些是上游/本地接口错误，不是 429 的替代证据。能力探测中的 404 不等同于实际功能请求失败。
- 对局详情最慢记录 `log_seq=195`：总计 8,558 ms、战绩阶段 7,447 ms、段位阶段 5,096 ms；另一条 `5371` 总计 7,059 ms、战绩阶段 6,949 ms。阶段存在并行，不能相加作总耗时。
- 推荐响应最慢 12,538 ms（`303`），其他慢记录为 7,556、5,944、5,654 ms。原来已有详情预热，但推荐依赖完整详情返回后才开始，仍然形成串行等待。
- 截图中的 Rookie 页签显示 TheShy 内容，与 `selectPlayerTab` 的 dirty 分支只安排稍后刷新、不立即渲染目标账号相符。若 dirty 重试已用完，这一分支不会再产生渲染。

## 实现

| 项目 | 变更与边界 |
| --- | --- |
| 阵营播报 | 支持合法聊天 JID，按路径段编码；一次选人阶段最多 3 次读取尝试，不再按 WebSocket 事件数量重复尝试。离开选人或禁用规则会取消等待与请求；写入结果不确定时不重复 POST。会话不足显示本次跳过。 |
| 自动开始匹配 | 非房主、自定义房间、房间未就绪显示具体条件，不再把条件不满足作为反复失败通知。真正接口失败保留失败状态。 |
| 页签串页 | 选择 dirty 页签也立即渲染该账号现有内容或加载状态，刷新只是后续更新，不再保留前一个账号 DOM。 |
| 韩服冗余刷新 | 本地对局结束只标记自己的账号和这场对局的参与者；不再把无关韩服页签全部标记 dirty 并触发多轮刷新。未提高或绕过 Riot 额度。 |
| 对局提前加载 | 延续后端阶段检测预热；识别到当前英雄后，在多人身份/战绩查询之前启动推荐预热，复用现有 provider 缓存及请求合并。切到其他页面或窗口隐藏时仍允许有限的阶段预热；相同进行中阶段事件不反复加载。 |
| 推荐预热边界 | 同模式、英雄、位置去重；成功 3 分钟、失败 30 秒冷却，15 秒请求期限，最多 32 个条目。未确认英雄、峡谷位置不明确时不猜测。新增 `live_recommendations_prewarm` 诊断事件。 |
| 详情加载 | 大乱斗不再请求不展示的排位段位。战绩请求失败不再标为完整快照并冻结整场；失败可有限补查，成功的战绩缓存继续复用。后台补查有次数上限。 |
| 海克斯缺少白银 | 移除按全局前 9/12 项提前截断的处理；数据合并后按品质取前三项，避免金色、棱彩占满列表挤掉白银。来源确实没有某品质数据时仍不编造。Hexdata 与 OPGG 推荐源并发读取。 |
| 大乱斗详情样式 | 删除玩家名下段位及无意义的“其他”；自己名称使用主题色。战绩、胜率、KDA 使用不同颜色。 |

## Hexdata 估算分：自动嵌入未实现

核对了官网页面与其网页请求契约。官网文章说明这是基于公开对局参与结构推导的相对位置，**不是 Riot 官方 MMR**：

- https://hexdata.com.cn/matchmaking-position
- https://hexdata.com.cn/articles/matchmaking-position

对网页使用的 `/v1/public/match-report` 做了一次空请求体核验，没有提交任何玩家身份。接口明确返回 HTTP 403：

```json
{"error":"web_lookup_only","message":"仅支持在官网查询，不支持机器人或脚本调用。"}
```

因此本轮没有自动查询、没有伪造浏览器凭据、没有填入假分数。KDA 后增加的是“海斗估算分 → 官网查询”入口，需要用户在官网查询；这不是用户所要求的逐个玩家自动显示数值。要实现自动数值，需要网站提供允许第三方使用的接口。

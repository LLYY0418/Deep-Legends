## 现象（用户截图）

- 窗口很大，遮罩卡片居中，但“激活 Deep Legends”标题下面直接被一个叠上去的对话框遮住：标题“隐私说明”、空白正文、一个“关闭”按钮，位置压在注册码输入框上。
- 对话框是**启动就在**的，没有点过“隐私说明”；正文是空的（还没读取隐私文本）；点“关闭”无反应。

## 根因（已核对代码）

`backend/web/index.html` 里隐私对话框是 `<dialog id="license-privacy-dialog" class="license-panel">`，而 `backend/web/app.css:273` 的 `.license-panel { … display:grid; … }` 作用到了这个 `<dialog>` 上。浏览器自带样式的 `dialog:not([open]) { display:none }` 优先级低于作者样式，**未打开的对话框被强制渲染成绝对定位的非模态方框**，盖在表单上。点“关闭”（`<form method="dialog">`）只会关闭一个本来就没打开的 dialog，所以没有任何效果。

测试没发现的原因：授权界面的单元测试在 JSDOM 里跑，JSDOM 不计算浏览器自带样式与作者样式的层叠，看不到这个问题；R233 的界面用例只检查元素存在与文案，没有在真实 Chromium 里验证“可见”与“可点击”。

## P1　修复隐私对话框

1. 让关闭状态的对话框不显示：在 `app.css` 中，让 `display:grid` 只作用于 `#license-privacy-dialog[open]`（或补 `dialog.license-panel:not([open]) { display:none; }`）。选其一，写清理由。保持打开时的布局、`::backdrop`、`max-height`、滚动不变。
2. **审计同类问题**：搜索 `backend/web` 下所有 `<dialog>` 元素以及用 `hidden` 属性控制显隐的元素，检查是否有作者 CSS 的 `display` 把 UA 的 `dialog:not([open])` 或 `[hidden]` 覆盖掉；逐个列出结论，有同类问题一并修复并补测试。
3. 隐私文本读取：现在是点击“隐私说明”后才请求 `/api/privacy` 再 `showModal()`，保持这个流程，读取失败时的提示“隐私说明读取失败，请重试”保持不变。

## P2　授权窗口使用固定的小窗口（700×470），不做分辨率自适应

用户要求：先只做“输入注册码”这一个小窗口，大小和安装窗口一样（`installer/window_windows.go` 里是 700×470，按 DPI 缩放；本单先**按 700×470 个 DIP 固定**，**不做按屏幕分辨率自适应缩放**）。

1. **未授权时的窗口**：只要授权状态不是 `ACTIVE`（含 `LOCKED / NETWORK_LOCKED / REPLACED / REVOKED / DEVICE_ERROR`），主窗口使用内容区 700×470、屏幕居中、不可最大化、不可拖大小；最小尺寸限制（现在是 780×600 乘以界面缩放，见 `desktop/main.cjs` 的 `applyUiScale`）在此状态下解除。此状态下界面缩放固定为 1（`.license-panel` 的 `zoom: var(--ui-zoom,1)` 也取 1），不随屏幕自适应。
2. **变为 `ACTIVE` 后**：恢复到用户原来的窗口大小与位置（`window-bounds.json` 里保存的值；没有则用 `initialWindowBounds()`；原来是最大化的恢复为最大化），再解除不可最大化/可调整大小的限制，恢复原最小尺寸。
3. **使用中又被锁定**（例如被别处顶替变成 `REPLACED`、被停用）：同样缩成 700×470 并显示遮罩，同时**记住锁定前的窗口大小**，重新激活成功后恢复。
4. **小窗口的尺寸绝对不能写进 `window-bounds.json`**：`resize/move` 触发的 `persistBounds` 在授权未生效期间不得保存，否则用户激活后窗口永远是小的。加测试。
5. **启动时不要“先大后小”的闪烁**：splash 之后显示主窗口之前就要确定窗口大小（授权状态在主窗口显示前确认；不是 `ACTIVE` 就直接以 700×470 显示）。**已授权且租约有效的用户启动时不应看到小窗口一闪**；如果现有启动顺序无法保证，请把实测情况（状态确认耗时、是否出现闪烁）写进账本，并选择对“已授权用户”影响更小的方案。启动耗时指标（R-启动阶段记录）不得变差，需要实测对比。
6. 实现位置由 GPT 决定：`license-ui.js` 在状态变化时已经调用 `window.desktopBackend.licensed()`，需要对应增加“未授权/已授权”的通知，由主进程切换窗口大小；同时保持主进程对页面输入的校验（只信任来自本应用页面的 IPC）。

## P3　小窗口里的授权页面设计

内容尺寸 700×470（含无边框窗口顶部 `titleBarOverlay` 的高度），整个界面**不出现滚动条**，竖向居中。保持现有深色与六边形风格，和安装窗口协调；**只调整排版，不新增说明性文字**（项目约定：界面不加“统计口径/说明/免责”类文字）。

1. 卡片宽度约 420，居中；从上到下：应用图标（56×56）、标题“激活 Deep Legends”、标签“注册码”、输入框、提示信息一行（固定最小高度，文案变化时布局不跳动）、全宽主按钮“激活”、**一行**两个弱化链接“隐私说明”“导出诊断”（左右分布，不再上下堆叠）。
2. 提示信息按状态区分颜色：普通提示用次要色；错误（例如“注册码已被其他地方使用”“无法连接激活服务，请联网后重试”）用警示色，但不要大面积着色。所有文案保持现有内容。
3. 输入框启动即获得焦点，回车提交；激活中禁用输入与按钮（现有行为保持）。
4. 隐私说明对话框在 700×470 里：居中，宽度不超过窗口减去边距，最大高度约窗口的 80%，正文可滚动，“关闭”按钮在底部，Esc 与点击“关闭”都能关闭；遮罩背景压暗但整体不遮挡标题栏的窗口控制按钮。

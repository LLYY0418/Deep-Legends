## 当前对局来源和准确性

### 韩服

检查了用户指定的 [JUGKlNG 玩家页](https://op.gg/zh-cn/lol/summoners/kr/JUGKlNG-kr) 的公开 JS 和实际响应：

- `getInGameInfo`（Next Action `40f052435807841afcefdd3e993b4a019b4a1bf970`），POST 同一玩家页面，参数只有 `locale/region/puuid`。
- **只读查询**，不是刷新账号、录制、导入符文或执行观战脚本。没有 Riot 历史分页，也没有逐个队友请求 Riot。
- 跟随 RSC 行 0 的 action 指针，读取 `summaryTeamsData.blueTeam/redTeam.participants`。不在其它历史对局中搜相似账号。
- 必须验证目标 PUUID 在当前阵容中恰好出现一次、十个不同账号、两队各五人、时间有效且未结束；异常不是“未在游戏”。
- 实际响应包含英雄、等级、技能、符文、`league_stats.tier_info`、近期英雄及技能/胜负、`recent_summary.most_position`、连胜/连败 badge。
- “首选位置”的来源实为 OP.GG 近期常用位置，不声称是玩家排队时手动设置的首选；tooltip 明确口径。
- 平均段位使用来源字段；仅当五人均有大师/宗师/王者 LP 时附加原始 LP 算术平均，低段位不会把各分段 LP 直接混算。
- 第一次真实读取为进行中、2×5 人、每人最多10场近期；随后该玩家查询返回 RSC `"$undefined"`。已验证这是页面使用的无当前对局结果，不当成字段解析失败。
- `OPGG_CURRENT_GAME_PROBE=1 go test -run TestOverviewCurrentGamePublicProbe -v .` 为显式联网核验，依赖本机 `/private/tmp` 的公开请求/响应样本；普通 CI 不联网。

### 国服（原始 R74 范围；2026-09-10 扩展见下）

- 当前已核实的链路是 LCU gameflow/session，**不是任意国服账号的 spectator 接口**。
- 先核对目标账号在本机当前阵容中，且查询大区与本机大区一致。其它玩家或跨服：`unsupported`，绝不把自己的游戏挂到别人总览。
- 本机参与的对局：展示实际英雄、技能、名字；经资料接口精确确认 PUUID 和 PUBLIC 状态后，利用现有按玩家/大区隔离的缓存补等级、排位和近期战绩。资料失败/私密/未知则不做战绩补读。
- 原始隐藏身份不还原展示、不补查。没有稳定身份的成员只显示客户端已提供的阵容字段。
- “常用位置”和至少三连胜/败仅从已读取、当前队列的最近战绩推导，tooltip 标明来源口径，不用本局分路冒充常用位置。
- 未核实的符文、游戏开始时间、平均段位不填，不把游戏内英雄等级当召唤师等级。
- 再次核对本机 phase/game ID，避免补读期间游戏结束或换局后显示旧阵容。
- 尚无 Windows 国服真实运行环境验收；本次通过 mock 验证查询与降级边界。公开 [Live Client Data 文档](https://developer.riotgames.com/docs/lol#game-client-api_live-client-data-api) 不能证明任意国服账号 spectator 可用，故没有伪造这项支持。

## UI / 请求隔离

2026-09-11 实测更正：代码会尝试使用 SGP GSM 查询不在本机阵容的同服玩家，但这不等于已验证支持任意好友阵容。2326 日志显示同一凭据查询本人返回 200，查询其他玩家返回 401；LeagueAkari 当前的 GSM 阵容调用也以当前登录账号为查询对象。此前“同服玩家可查询当前阵容”的表述把 mock 契约测试通过误当成了国服可用性，应以 [2326 实测分析](diagnostics-0911-2326.md) 为准。隐藏战绩仍不直接阻断当前对局尝试，但限制个人战绩补读；缓存仍隔离登录账号与 LCU 客户端。

- 独立卡片置于第一个战绩条上方，标题“正在进行的游戏”。蓝红两队，窄内容区纵向排列，沿用主题变量。
- 不包含 OP/LN Score、MVP、ACE、补刀奖牌或英雄类型标签。额外标签仅位置与连胜/败图标，并有可访问名称。
- R74：近期默认 8 场、队伍内容宽 ≤372px 时 6 场，超出整项隐藏；位置/连胜徽章与段位各自十行左对齐。卡内胜绿负红，战绩列表的胜蓝不变。
- 近期项下方的技能小图标移入 tooltip，仅使用真实技能目录名称；目录晚到自动补全，即使玩家没有历史战绩也会加载。行首本局技能/符文保留。
- 连胜/败使用 17px SVG，段位/LP 使用等宽数字，时钟持续保留“已进行”。
- 韩服观战按钮打开 OP.GG 玩家当前对局页面；不执行来源里的 Windows/macOS 脚本，不宣称已在客户端发起观战。
- 30秒刷新当前可见玩家，1秒更新已知时长；后台页签/隐藏窗口停止轮询。刷新当前对局不会刷新战绩。
- 后端10秒缓存、最多64账号、2个并发账号，同账号singleflight；独立12秒超时，不占 Riot 战绩限额。
- 仅接收会话匿名 playerRef；返回亦为匿名引用。PUUID、令牌、来源脚本与不展示的评分不进入响应。
- 失败显示“暂时无法确认”及重试，不保留旧游戏冒充当前游戏，也不假装没有对局。

### R76 收尾口径（2026-09-09）

- 总览分组采用方案 A：不改样式/箭头/tooltip；测量完整 `.player-workspace-head` 顶到 `.summoner-strip` 顶，桌面1440/1100/820验收≤76px，三主题实测75px。620两行133px不套桌面阈值。旧69px量的是低6px的按钮顶，不是完整head顶。
- 职业符文遵循“保留已取得且可核验的数据、明确缺失范围”的降级原则。响应新增 `totalGames`，`failedGames` 按game ID去重，覆盖索引、终局与本次选中英雄的详情补读；同一局失败多次只计一局。
- `totalGames` 是本轮已知、纳入索引窗口的对局与单局索引失败ID的并集；不是赛事历史全部局数。失败索引若没有起始时间，只能按已筛选系列中的已完成候选局计入，不能断言其精确开局时间。无法读取的赛程/系列局数未知，不伪造进分母，单独标记来源不完整。
- **严格超过10%** 才提示“部分职业赛事数据加载失败”并提供重试：少量失败（1/99或1/10）只显示未补齐数量，保留可用推荐，不说整个来源不可用；10/30显示部分降级。10%为提示阈值，不改变任何推荐筛选、选手身份或胜负判断。
- `stale` 独立表达全局来源刷新失败、缓存过期、目录读取失败或存储异常。单局失败不直接将整份数据标为旧缓存；完整赛程/系列读取成功后索引读取时间更新。真正离线/全局失败仍显示明确原因和缓存读取时间，不以低失败率掩盖。
- 详情补读是按英雄按需进行，因此失败数描述“已尝试范围内未完成的对局”，不声称后台已校验所有英雄的完整符文。

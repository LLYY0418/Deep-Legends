# OP.GG 玩家总览赛季英雄汇总

## 实测依据（2026-09-08/09）

用户指定页面：<https://op.gg/zh-cn/lol/summoners/kr/JUGKlNG-kr>。

公开前端组件 `83594` 调用 `getSummaryRankedMostChampions`。当前发布脚本为 `4272-53760d39bee2463d.js`，action 为 `4028494596c44675d8e9f617b8f659312f3b678072`。

查询输入来自页面自身的当前赛季：`locale=zh-cn, region=kr, season_id=33, game_type=RANKED`，PUUID 必须匹配本会话已核验的玩家。不是从 URL 推断赛季编号，也不把 Riot 的赛季编号拿来代用。

返回是服务端已聚合的记录：一个 `is_all_champions=true` 总计，加侧栏常用英雄（本次为 7 个）。首次查询为 S2026、573 场、323 胜、250 负；随后用生产 Go 请求代码实测为 574 场、324 胜、250 负（4.75 秒）。说明是动态查询结果，不是硬编码数据。

页面“赛季”默认范围为 RANKED（单双排 + 灵活排位），不是所有游戏模式。常用英雄的场次不能相加代替全部英雄总计。KDA 的 `kill/death/assist` 是累计值，界面须使用 `avg_kill/avg_death/avg_assist`。

## 本项目接入

- 新增授权接口 `POST /api/gameplay/season-summary`，仅接受会话内匿名玩家引用；拒绝原始 PUUID、非 KR 和私密玩家。
- 初次冷查询为一次页面元数据 GET + 一次汇总 POST；不请求 Riot、不扫描历史对局、不启动分页回补。
- 前台战绩返回后独立加载，汇总完成仅更新对应玩家的生涯统计区，不重查整个 Riot 总览。普通/职业页签各自保存状态，按 playerRef 校验延迟结果，关闭页签取消请求。
- 按账号单飞和缓存；成功 10 分钟、失败短暂退避、手动刷新有 15 秒防抖；最多 4 个并行账号、64 项缓存。两步请求共享 15 秒上限，与原有英雄数据网络设置共用连接通道，不占 Riot 配额。
- 英雄名/ID 通过本项目的英雄 Key/Slug 映射；不信任第三方图片 URL。未知英雄、总场次不一致、字段缺失、action 结构变化均降级，不伪造数据。
- 使用 OP.GG 的实际赛季标签；页面展示 `S2026 · OP.GG · N 场排位`。只展示该侧栏返回的常用英雄，不声称已返回完整英雄池。旧汇总刷新失败时标记缓存；没有可用汇总则保留明确标注的近期样本。
- action 是公开网站的内部查询契约，不是稳定开放 API。网站发版可能使其失效，届时明确降级；不能把已接入说成永久可用，也没有推断其服务端内部如何存储/计算历史数据。

- 生产 Go 完整联网查询成功：574 场、324/250、7 个常用英雄。

- 测试覆盖 action 结果引用（忽略混在 RSC 中的对局记录）、整体/Top 英雄分离、场次一致性、匿名引用/隐私保护、单飞/缓存、防串号、失败不回补及原有分页保留。

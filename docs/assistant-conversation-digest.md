## 用户反复强调的原则（合并两端）

1. **数据准确性红线**：皮肤匹配不遗漏、FetchedAt 不许「撒谎」、recency 判断必须准确、职业名单/奖励数量精确核对；隐私声明必须与实际写操作一致（「声明准确性是有红线的」）。
2. **隐私与凭据**：neverStores 声明 vs 明文 PUUID；API Key 不入仓库（gitignore/密文）；关心 Key 能否被从安装包提取；关注 Riot 额度消耗。
3. **数据源优先级**：国服走客户端/LCU；韩服 Riot API > OPGG；海斗/斗魂 hexdata 为主、OPGG 兜底；忌讳第三方数据纠纷与异常流量。
4. **写操作安全**：符文/装备方案不得覆盖用户数据，须可回收、可识别（`[DL]` 前缀）。
5. **视觉纪律**：海克斯黑金风格、设计图 100% 还原（「完整还原」「不要遗漏任何一点」）、全站样式/高度/颜色统一、胜率字体颜色大小一致、全中文文案（英文枚举译中文）。
6. **性能与体积**：企业级标准、轮询降频、翻页流量失控要根治、压缩级别 9、清缓存但「绝对不可以影响到功能」。
7. **工程纪律**：工单驱动（「按照这个工单执行」+「不要遗漏」高频出现）、日志完备（「把能想到的地方都补上日志…以防下次问题还是找不出来」）、性能改动必须加护栏/变异测试、验收只看实跑不自述。
8. **打包纪律**：必须重新构建确认最新版本号；旧二进制曾用假数据骗过验收；用户自己打包（「你改好问题就行了，不要打包」）。
9. **验收方式**：截图→指出具体像素问题→改；Windows 真机 + diagnostics.jsonl + 录屏。
10. **沟通偏好**：中文、简短直接（「简短易懂的回答我」「给我确定答案」）、不询问直接执行、讨厌超范围改动（「瞎改」零容忍）与冗余交互（去提示框、不二次确认）。

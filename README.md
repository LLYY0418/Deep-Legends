# Deep Legends

Windows 本地英雄联盟助手。无需启动游戏客户端即可联网查看韩服英雄梯度、符文、出装和海克斯推荐；玩家正常登录国服客户端后，还可在本机查看召唤师生涯、最近战绩、实时对局、皮肤收藏和三合一奖池。绝大多数功能只读取公开数据或客户端；只有玩家明确点击应用、领取或维护动作，或在“工具 › 自动”逐条开启默认关闭的自动规则时，才会向本机客户端发送对应操作。

> 本项目不是腾讯、Riot Games 或英雄联盟官方产品，也不提供自动合成、分解、购买或账号登录功能。

## 直接运行（桌面客户端）

当前只生成 **Setup 安装版**：双击 `dist/desktop/Deep Legends Setup <version>.exe`，在深色金色无边框安装界面中选择目录、桌面快捷方式并阅读同意条款，点击开始安装。进度到 100% 后继续显示启动进度，等应用窗口可见再关闭安装器，最多等待 20 秒，没有独立完成页。新安装默认当前用户，安装器不请求提权；受保护目录会在安装前报错，旧版默认路径优先从当前用户卸载注册表读取。开始菜单快捷方式、覆盖升级和卸载由现有 NSIS 安装逻辑处理。缺少 WebView2 运行时时显示明确的启动错误，不再自动切换旧安装向导。安装版每次启动直接运行安装目录中的程序，没有任何释放步骤；卸载入口在“设置 → 应用”。

启动后先出现启动页，本地数据服务加载完成再显示主界面。如果英雄联盟尚未运行，仍可直接使用“英雄”页；也可在未连接首页选择程序检测到的国服纯净入口或 Riot 客户端，登录并进入大厅后会自动读取收藏。

窗口可以自由缩放。左侧一级导航为“总览 / 英雄 / 对局 / 收藏 / 工具”，连接状态与设置固定在底部；收藏顶部使用紧凑的横向二级导航容纳皮肤、账户和三合一奖池，工具下含自动、维护、生涯、领奖和征召五页。页面会随窗口宽度调整；顶部提供召唤师搜索（国服可从艾欧尼亚、黑色玫瑰、联盟一区至五区、峡谷之巅和体验服中选择具体服务器，韩服单独选择；名称与 # 编号分栏，粘贴完整 Riot ID 自动拆分；韩服可只填名称，编号由公开搜索补全后再精确查询）与带在线人数徽标的“好友”按钮，主题、界面密度、默认页、英雄默认位置、战绩展示数量与默认筛选、实时对局排序和刷新间隔、隐私遮罩及回放操作确认按分类页签收纳在“设置”；自动接受、快速下一把、断线重连及其余流程托管规则统一在“工具 › 自动”逐条配置，英雄选择阶段的禁用、选用、备战席与换英雄请求在“工具 › 征召”配置。离开某个主页面后再进入，该页的页签与筛选项会还原为默认；总览页内在玩家页签之间来回切换时，各页签的筛选、战绩展开与详情页签互相独立保留。

桌面主程序会隐藏启动内置的本地数据服务。服务只监听随机的 `127.0.0.1` 本机端口，启动握手使用每次随机生成的会话令牌；令牌只保存在进程内存中，不写入磁盘，也不会上传服务器。

### Windows 安全提示

构建脚本支持使用可信代码签名证书文件进行 Authenticode 签名，并在构建后生成 SHA-256。没有提供证书时会明确生成未签名开发版，Windows SmartScreen 仍可能显示“未知发布者”；代码本身无法绕过这一信誉机制。

公开分发建议同时提供：

- 受信任证书签名的安装版与便携版 EXE；
- 包含 EXE 的 ZIP；
- `SHA256SUMS.txt`；
- 发布页中的版本说明和扫描结果。

## 功能

- “英雄”无需登录客户端即可按需联网读取 OP.GG 韩服单/双排梯度及详情，并提供全部、上单、打野、中单、下路、辅助位置和最强王者至铂金及以上段位切换。搜索支持中文、英文、拼音、首字母缩写与常见外号；海克斯大乱斗页展示英雄梯度、完整强化符文目录、描述和适合英雄，详情优先呈现推荐海克斯，再复用召唤师技能、技能顺序和出装组件；斗魂竞技场页展示英雄梯度与三人队伍协同榜（平均名次、第一名率、选用率、胜率），详情提供推荐三人队伍与推荐海克斯。最强王者等高分段样本不足时，整页或仅对抗数据回退到翡翠以上并在界面标注实际口径。
- “总览”按当前召唤师和新打开的玩家标签展示单排/双排、灵活组排、英雄胜率、位置偏好、熟练度、过去 30 天排位、最近 30 天同场玩家、活跃时段及最近战绩；排位使用官方段位徽章，当前登录账号的标签固定第一并以金色高亮。战绩卡与对局详情附带单场相对评分和 MVP / SVP 标记：按 KDA、参团率、伤害、经济、补刀和视野相对同场玩家加权计算，仅供参考，不代表官方口径。在总览页点击玩家名称会打开可关闭的新标签；在对局页或英雄详情页点击玩家名称则在当前页面以覆盖层展示总览，左上角“返回”回到原页面。国服已结束对局的详情通过腾讯官方 SGP 网关读取，令牌来自本机已登录客户端。国服玩家总览不再查询或展示当前对局、好友游戏状态卡及对照探测；韩服当前对局保留。本机“对局”页和好友列表状态不受影响。
- 顶部搜索框支持国服具体子服务器与韩服：国服先通过本机 `RiotClientServices` 的全局 aliases 接口把精确 `游戏名#编号` 解析为内部 PUUID，再使用当前已登录 League Client 提供的 league-session 令牌向所选腾讯 SGP 子服读取召唤师和战绩；两套本地服务的端口与令牌彼此独立，不会写盘或返回渲染页。国服排位接口只能读取当前登录服务器，打开其他子服玩家时排位卡会明确显示“跨服暂不支持排位”。韩服玩家通过 Riot 官方开发者 API 精确查询，段位、熟练度、最近战绩与国服玩家使用同一套总览界面。韩服允许只填名称：官方接口找不到时，本机服务会向 OP.GG 公开搜索补全编号，再回到 Riot 查询。API Key 以密文形式内嵌：先运行 `go run . -encrypt-riot-key "RGAPI-你的key"`，再用 `-RiotAPIKeyCipher` 参数（或环境变量 `RIOT_API_KEY_CIPHER`）在构建时注入，源码中的 `riotAPIKeyCipher` 变量本身永远留空，不会提交到仓库（密文只能防止从源码中直接扫出明文，不能阻止拿到 EXE 后抓包或逆向提取，请自行评估分发范围；泄露后可到开发者门户重置）。官方 API 不覆盖国服；汇总统计基于当前已读取的战绩样本，单场详情在本机内存缓存以节省接口配额。
- 搜索大区下拉中，国服子服务器每次打开默认折叠；韩服下方的“职业选手”是独立页面入口，不改变搜索服务器，也不新增侧栏菜单。仅展示 BLG、IG、T1、HLE、GEN、DK 已核对的一队选手，按选手分组、单双排段位/小段/LP降序列出可核验韩服账号。支持队伍/选手/账号筛选、主题切换和进入现有韩服总览后返回。账号来自 OP.GG 完整韩服目录与已审查的 TrackingThePros 实名页，缺失、未知、不活跃与旧缓存明确标注；名单日期与来源边界见 `docs/pro-players-sources.md`。这不等同于“对局”页的职业选手符文推荐功能。
- 服务器归属规则：韩服与每个国服子服务器互不相通。搜索栏按所选服务器查询；点击页面内出现的玩家名称时沿用当前页面所属的具体服务器，时间线、分页和异步缓存也保持相同作用域；跨服排位与依赖逐人排位的平均段位不受客户端接口支持，分别明确显示能力边界或“—”。英雄详情页的玩家榜来自 OP.GG 韩服数据、固定按韩服打开。玩家页签与总览头部会标注“艾欧尼亚”“黑色玫瑰”等具体子服或“韩服”。隐藏名称和主播模式只遮罩身份显示；英雄选择阶段的标准 `obfuscatedPuuid` 在后端本地恢复为内部引用，然后与普通玩家使用相同的可用数据管线。
- 战绩可直接筛选单排/双排、灵活组排、海克斯大乱斗与斗魂竞技场，其余队列在“更多模式”中选择。单场卡片可展开双方概览、队伍分析和构建：队伍分析用红蓝双色对比条呈现击杀、金币、伤害、视野等六项指标；构建页展示结算装备、按分钟分组的装备购买路线（含出售记录）、真实的技能加点顺序（主升/副升摘要）和完整符文树。装备路线与技能加点来自对局时间线：国服优先读取本机客户端，其次官方 SGP 网关；韩服来自 Riot 官方 timeline 接口；读取不到时明确降级，不用英雄默认顺序代替。回放按钮点击后直接交由英雄联盟客户端处理，需要先下载的回放会在下载完成后自动开始播放（官方回放仅保留当前客户端版本的对局）。
- 战绩卡左侧是模式、相对时间、结果与时长；中间是英雄头像、召唤师技能、主系基石与副系符文、K/D/A 和单场评分，下方按客户端原始槽位展示装备与饰品（空槽保留占位框），并附评分排名、MVP / SVP、多杀与零阵亡徽章；再向右三行数据分别是击杀参与率、补刀（悬停可见小兵与野怪拆分及分均补刀）和本场平均段位；最右列出本场玩家，点击即可打开该玩家总览。卡片按战绩栏自身宽度自适应，窄窗口下依次收起玩家列表并把数据行改为横排。
- 单双排与灵活组排的战绩会显示这一场的胜点（LP）增减。官方接口（本机客户端、Riot、SGP）都不提供单场胜点变化，本地服务改为在对局结算时读取排位数据并与赛前基线比较得出。`lp-history.json` 使用 `schemaVersion: 1`：基线键和游戏记录都只保存由本机随机盐与账号内部标识计算的 SHA-256 前 16 位小写十六进制 `accountHash`，不保存 PUUID；文件以 `0600` mode 参数原子写入，最多保留 400 条最新游戏记录。旧 schema、非法哈希或损坏文件会被清空重写，不迁移其中的明文标识。因此只有助手运行期间打的排位才有这个数字，更早的历史对局无法回溯，其他模式不显示。
- 平均段位：当前登录的国服服务器通过本机客户端逐人查询本场参与者的排位后取平均，界面按卡片懒加载回填并在本机缓存 10 分钟；跨服不受排位接口支持，显示“—”。韩服逐人查询会超出 Riot 接口配额，改为按开局时间与时长匹配 OP.GG 公开对局数据里的平均段位。大师及以上附带平均胜点。取不到时该行显示“—”，不以推断值代替。
- 斗魂竞技场按 21 人、3 人一队完整展示：战绩卡右侧按小队分列全部玩家、第一名小队高亮，左侧显示本队名次而非胜负；展开后概览与队伍分析都按名次分组呈现七支小队。击杀参与率与评分中的参团维度按本小队三人的击杀合计计算，不使用在该模式下无意义的红蓝方汇总。
- 顶栏“好友”按钮打开右侧只读好友面板：分组、顺序、折叠初始态与备注完全来自本机客户端，离线好友统一归入底部“离线”组并显示最近在线时间，组内按游戏中、在线、离开、手机在线排序；游戏中的好友显示队列、英雄与实时时长，点击任意好友即在总览页打开其战绩。面板不提供好友增删改或消息功能，未连接客户端时按钮禁用。
- “对局”在英雄选择或游戏进行时展示双方玩家、当前队列的近期胜负/胜率/KDA，英雄选择阶段每 3 秒自动刷新；游戏开始后数据齐全就停止自动刷新，斗魂尚未分组时先在每个加载/游戏阶段的前 60 秒每 5 秒探测，随后数据未齐每 20 秒重试、最多 8 次，页面保留停止状态与“刷新”按钮，并支持按位置、KDA 或胜率排列玩家。“详情”页签中每名玩家的最近战绩只统计当前队列；单双排和灵活组排的玩家卡片还显示已读取的最近 10 场内各位置的使用场数，1 场也展示，无有效位置记录则隐藏，不为此额外拉取战绩。点击玩家名称跳转到总览页查看完整生涯。OP.GG 综合符文已经接入；绝活哥符文使用独立懒加载链路：取 OP.GG 韩服专家榜前两名玩家，经 Riot 官方接口在每人最近 10 场对局中最多检查 8 场，只返回目标英雄且主系、副系和符文完整的真实配置，同时标注玩家、段位、英雄场次、对局时间与胜负；结果按英雄在进程内缓存 6 小时，取不到时保持空态，不用其它英雄或聚合数据冒充。职业选手符文使用 LoL Esports 官方公开赛事接口，仅收录已核对六支一队在 LPL/LCK/First Stand/MSI/Worlds 近 30 天的比赛；每英雄最多 5 套，最新在前，展示同路对位、赛事标签、已确认战绩和最终装备。未知胜负不计入胜率，少于 3 场不显示百分比；属性碎片不完整时禁止应用。后台索引与按英雄懒补齐使用独立公开传输，缓存过期或失败明确标记并提供重试。客户端自身返回的推荐符文可作为备用。英雄选择阶段点击“应用到客户端”会直接新建一页以“[DL] 英雄名 · 推荐来源”命名的符文并设为当前页；若客户端页数已满，只读取页面名称、删除许可、修改时间与 ID，并最多删除 5 个本工具此前创建的、名称带精确“[DL] ”前缀且未显式标记为不可删除的最旧页面来腾位，绝不删除、更新或覆盖其它符文页。没有可回收页面时停止并提示玩家手动删除一页；改版前没有前缀的旧页面不会迁移或回收。出装推荐旁的“应用装备方案”只在英雄选择阶段启用；点击后写入游戏 `Config/Global/Recommended` 下本工具固定 UID 的推荐文件，采用与 LeagueAkari 对齐的精简结构，并保留一份上次内容备份。写后核验成功才尝试清理精确匹配本工具旧 UID 的账号方案；清理前再次核对账号与原文档，有变化就保留现有方案。不会清理用户自建方案或修改游戏 HUD、`game.cfg`、`PersistedSettings.json`；实际游戏内商店布局仍需 Windows 实机验收。
- 兼容性边界：Riot Client 的 `aliases/v1/lookup`、腾讯 SGP 的 `summoner-ledge` 和 League Client 的 `lol-item-sets` 都是没有官方稳定性承诺的客户端私有契约。目前只有 macOS 上的本地 mock 自动测试，尚未完成 Windows 国服客户端真机验证；在三条链路逐项通过真机烟雾测试前，它们都按实验性能力处理，不能作为已完成的发布验收项。读取失败会明确降级，跨服失败不会回退到当前服务器数据；装备方案写入仍要求英雄选择阶段和玩家明确点击。
- 收藏页提供已拥有、全部皮肤和全部炫彩三个视图；已拥有默认首先展示。
- 战绩展示数量可设为每批 10 / 20 / 30 / 40 / 50 场；滚动到列表末尾会按同一批次自动继续读取。
- 全部皮肤通常按英雄分组；选择品质筛选或品质排序时改为按品质和神话子类分组。已拥有皮肤保持原画，未拥有皮肤置灰并显示锁。
- 全部皮肤可按英雄熟练度、皮肤数量、英雄名、品质或获取时间排列。获取时间模式以每位英雄最近获得的已拥有皮肤决定英雄分组顺序。
- 全部炫彩与普通皮肤、三合一奖池分别核对：国服臻彩按腾讯官方臻彩藏品清单与客户端炫彩 ID 交叉识别，在普通炫彩上方使用高清横版独立原画，可单独关闭“显示臻彩”。普通炫彩按所属皮肤分行横向平铺；普通滚轮始终上下滚动页面，触控板横滑、`Shift + 滚轮`或行内左右箭头用于横向浏览。默认同时展示已拥有和未获取项目，可关闭“显示未获取”。
- 皮肤和炫彩详情支持上一款、下一款与全屏原画；皮肤在同英雄内切换，臻彩在臻彩之间切换，普通炫彩在同一所属皮肤内切换。
- “三合一奖池”提供奖池目录、清单上传和本地历史三个页签，目录可分别查看已拥有与未拥有皮肤，并按精简后的奖池品质筛选。
- 搜索皮肤名、英雄名和 ID，并按英雄、品质、名称、获取时间或 ID 排序。
- 皮肤详情按需读取 RP 价格、库存 `purchaseDate` 和加载界面边框所有权；缺少可核验字段时明确降级，不推测结果。
- 普通皮肤与炫彩预览使用本机客户端备用路径，图片失败会自动重试，本机路径全部失败时按皮肤 ID 从固定的腾讯官方图片域名降级读取横版原画；臻彩独立插画按需从固定的腾讯官方图片域名读取并在本机缓存。客户端提供动态 WebM 时优先播放，并将“联盟不朽”任务皮肤形态作为独立原画条目展示。
- 库存来源状态、目录指纹、奖池哈希和映射完整度写入本机脱敏日志；测试用核对详情不占用正式客户端导航。
- 客户端启动、收藏变化或手动重新读取时会自动更新界面并显示读取进度。
- “账户与物品”只读页：按精粹、钥匙、皮肤、其他战利品和奖励分区展示；皮肤类库存会按稳定皮肤 ID 显示客户端中文名称。
- 只读接口能力检测：客户端不支持的附加端点会单独降级，不影响皮肤剩余计算。
- JSON、CSV、离线 HTML 导出；CSV 会防止公式注入。
- “设置 › 导出位置”供分享图与诊断日志共用；已设置的目录有效时日志直接保存到该目录，文件名冲突自动加序号，不覆盖旧日志。未设置、目录失效或无法接管下载时使用系统保存对话框。
- 最近 30 份本地脱敏快照位于“三合一奖池 / 本地历史”，同账号、同奖池版本之间可以比较变化。
- 导入并显式切换 TXT、单列 CSV 或 JSON 自定义奖池；每份清单都有规范化 SHA-256。
- 原生桌面窗口、Windows 任务栏图标、可收起图标侧边栏、紧凑模式和响应式布局；主题在设置中选择：自动（昼夜切换）、浅色、海克斯黑金、寒冰蓝、翡翠绿、星域紫、血月红、极光青、纯黑 OLED。背景保持中性深色，主题色只出现在主色、选中态和描边上。
- “工具 › 自动”的九条流程规则与“工具 › 征召”的独立托管能力可在本机客户端已连接时代劳对应动作；总开关和每项规则默认全部关闭，配置保存在本机数据目录。
- 征召总开关和自动选用开启后，在预选阶段自动提前亮出选用序列中的合适英雄，无需额外开关；正式选用仍遵守配置的锁定策略。“避让队友预选”关闭只允许选择队友仅预选的英雄，已被队友选择的英雄仍会跳过。自动禁用只在正式禁用阶段执行，并通过客户端状态确认结果，HTTP 返回成功本身不视为操作成功。
- 排位（单双 / 灵活）的禁用不分位置，共用 5 个有优先级的备选；选用仍按本局分配位置使用对应序列。旧分路禁用池按未分配、上单、打野、中单、下路、辅助去重合并前 5 个，原有效配置保存在 `legacyLaneChampions` 备份中，不参与执行，也不会回填用户清空的序列。
- 未连接时优先检测并启动桌面或开始菜单中的英雄联盟、Riot Windows 快捷方式，找不到时才使用已验证的安装目录；接口不接受任意程序路径。

## 准确性规则

- 奖池原图结构确认有 554 个非空条目；内置清单已经人工最终确认并核验为 554 个唯一稳定皮肤 ID，名称只作审计标签。
- 内置奖池直接用稳定皮肤 ID 核对当前客户端，避免改名、错别字或相似炫彩名称导致错配；自定义纯名称清单仍严格要求唯一匹配。
- 已拥有库存只接受明确的 `owned=true`、`OWNED`、`PURCHASED` 或专用皮肤库存端点中的实际条目。
- `AVAILABLE`、免费轮换、商城可购买状态不视为已拥有。
- 优先采用完整显式收藏来源；只有专用 `CHAMPION_SKIN` 实际库存完整包含至少两份显式来源时，才允许用库存补齐显式接口遗漏。成功空集合是合法的零库存结果。
- HTTP 404 视为当前客户端不支持该端点；临时失败、无效 JSON、未知 ID、单一来源或任意集合冲突都会停止计算。
- 皮肤目录只读取普通皮肤对象，并同时按嵌套层级、炫彩分类/父皮肤字段和 ID 范围排除炫彩及其他库存附属项；基础皮肤不计入收藏目录。
- 获取时间只接受皮肤库存明确返回的 `purchaseDate` / `purchased` 等购买时间字段，并交叉合并三路库存来源、校验时间范围；未拥有皮肤不显示获取时间。
- RP 价格只接受商店皮肤详情中明确标记为 RP 的金额；含糊或互相冲突的价格字段不会展示为确定价格。
- 边框必须先由对应皮肤的静态 `skinAugments` 证明存在，再以边框内容 ID 与专用库存精确匹配；仅有边框素材不等于账号拥有。
- 目录必须达到皮肤/英雄数量下限，并为每个活动英雄包含对应基础皮肤；目录指纹会写入可导出的本机脱敏日志。
- 名称近似匹配只用于给出修正建议，不会自动计入奖池。
- 只有 554 个奖池条目全部唯一映射成功时才显示剩余结果；否则停止计算并列出待核对项。

计算公式：

```text
三合一剩余 = 国服公告奖池皮肤 ID 集合 − 当前账号已拥有皮肤 ID 集合
```

奖池来源和原图位于 [`data/README.md`](data/README.md)。

## 从源码构建桌面客户端

要求 Go 1.24 或更高版本、Node.js 22 或更高版本。桌面外壳使用 Electron 43 和 electron-builder 26；WebSocket 事件订阅使用固定版本的 `github.com/gorilla/websocket v1.5.3`。Node 与 Go 的依赖校验分别记录在 `desktop/package-lock.json` 和 `go.sum`。

Windows PowerShell：

```powershell
./build-desktop-windows.ps1
```

指定版本并使用证书库中的代码签名证书：

```powershell
./build-desktop-windows.ps1 -Version "0.11.2" -CertificateFile "你的代码签名证书.pfx" -CertificatePassword "证书密码"
```

带上真实 Riot API Key（先用 `go run . -encrypt-riot-key "RGAPI-你的key"` 生成密文，只在自己本机构建时使用，不要提交到仓库）：

```powershell
./build-desktop-windows.ps1 -RiotAPIKeyCipher "上一步生成的密文"
# 或者用环境变量，避免密文出现在 shell 历史记录里
$env:RIOT_API_KEY_CIPHER = "上一步生成的密文"
./build-desktop-windows.ps1
```

更省事的方式：在项目根目录新建 `riot_key.local.txt`，第一行填明文 key（`RGAPI-...`），这个文件名已经在 `.gitignore` 里，不会被提交。以后每次直接跑 `./build-desktop-windows.ps1`（不加任何参数），脚本会自动读取这个文件、调用 `-encrypt-riot-key` 生成密文并注入构建，不用每次手动生成密文或设置环境变量。命令行参数和环境变量优先级都高于这个文件。

上述默认 `private` 构建仅供本人使用，必须提供密文或 `riot_key.local.txt`，不得上传公开 Release。公开构建使用 Windows 的 `-KeyMode public`，或 macOS 的 `DEEP_LEGENDS_KEY_MODE=public bash build-desktop.sh 0.12.1`：它不读取本机 Key 文件或密文环境变量，并显式清空后端的内嵌 Key。打包前和打包后均会检查凭据边界。

公开包默认保留国服本地客户端功能；韩服账号、段位、战绩、竞技场详情和绝活哥符文等 Riot API 查询需要使用者在启动应用的环境中自行提供 `RIOT_API_KEY`。未配置时沿用现有的明确提示／空结果降级，且不发送 Riot API 请求。运行时 Key 只用于本机向固定 Riot 官方域名发起请求，不会写入公开构建物。

每次构建在设置页显示版本和构建指纹；Setup 文件名仅使用版本号，源码指纹继续用于诊断和发布校验。构建目录保留 `release-build.json` 和 `SHA256SUMS.txt`；下一次构建会清理旧产物。R83 最新安装启动验证只需正常安装一次，提供 `%TEMP%\DeepLegendsSetup-startup.log` 和 `%LOCALAPPDATA%\LOLLootAssistant\logs\diagnostics.jsonl` 两个文件，不需要多份构建或 A/B 脚本。以 `spawn_to_ready` 为主判据，`launch elapsed_ms` 仅作参考，完整操作见 [执行预热默认关闭验收报告](docs/history/ACCEPTANCE-REPORT-R83-READ-ONLY-DEFAULT.md)。

Windows 脚本会检查 `gofmt`、运行测试与 `go vet`、校验前端和 Electron 主进程 JavaScript，将 Go 后台编译为无命令窗口的 Windows GUI 程序。两条构建脚本只生成 `Deep Legends Setup <version>.exe`、构建收据和 SHA-256，不生成便携版、独立 ZIP 或源码压缩包。安装版先生成现有 NSIS 包，再通过 `installer/build-shell.cjs` 嵌入独立 Go/WebView2 外壳；验证外壳为大于 50 MB 的 x64 GUI 程序后才计算哈希，并在核验完成后清理临时 payload 与 `win-unpacked`。未提供证书时构建仍可运行，但 Windows 可能显示“未知发布者”。

macOS 继续运行 `./build-desktop.sh`；需要内部计时信息时使用 `DEBUG=electron-builder ./build-desktop.sh`。`beforePack` 默认使用 7z 压缩级别 **9**，优先控制安装包体积；保留原有 NSIS 解压格式和兼容过滤器。环境变量 `ELECTRON_BUILDER_COMPRESSION_LEVEL` 仍允许显式覆盖为 0–9，正常构建无需设置。脚本继续复用已有 Electron 下载缓存；Bash 每 15 秒报告阶段耗时。`SKIP_SETUP` 已移除，构建始终生成 setup。`desktop` 内的 `pack:win` / `pack:win-setup` 只是内部 NSIS 步骤，最终分发应使用根目录完整构建脚本生成的外壳安装器。

`installer/` 是独立 Go module，根模块测试不会覆盖它；安装／卸载外壳验证请另行运行 `cd installer && go test ./... && go vet ./...`。没有内嵌 payload 的安装器开发构建仍可交叉编译，在具备 WebView2 的 Windows 上会显示安装包不完整的失败页。原 NSIS 向导和 Core 卸载逻辑保留，发布前仍需在 Windows 真机验证安装、升级、卸载，以及安装器缺少 WebView2 时的错误提示。

卸载入口使用同一视觉风格的 700×460 无边框确认页，默认保留数据。勾选“同时删除我的本地数据”时，Core 清理 Electron 的 `%APPDATA%\Deep Legends`，成功后外壳再清理 `%LOCALAPPDATA%\LOLLootAssistant`；缓存被占用只提示，不阻断完成。卸载时显示关闭客户端、删除文件、清理快捷方式与注册表三个步骤，100% 停留 1.2 秒后自动关闭。静默 `/S` 调用跳过全部界面，缺少 WebView2 时交互式调用回退原 Core 向导。

构建时先编译不含 payload 的 `installer/uninstall` 到 `desktop/uninstall-shell.exe`，再让 NSIS 的 `customInstall` 钩子将真实卸载器移至 `resources/uninstall-core.dat`、将外壳放到原卸载文件名 `Uninstall Deep Legends.exe`，并清理旧版根目录 Core 卸载器；注册表卸载入口不变。两条脚本均在成功或失败收尾清理生成的卸载外壳。

R83 当前默认只开启读预热，安装完成后完整读取最终目录中的主程序和后端两个 EXE，预热阶段不启动或强杀进程。执行预热默认关闭，日志明确记录 `startup warm mode=execute enabled=false`；仅在启动安装器的环境中显式设置 `DEEP_LEGENDS_STARTUP_EXECUTE_WARM=1` 才开启实验性执行预热。2026-09-12 20:22（指纹 `d2212835fcb1`）曾发生安装后首次启动主窗口未出现、splash 永久停留的故障；执行预热的因果关系和额外收益均未证实，因此默认关闭。显式开启时保留最终文件稳定 400ms、共享 8 秒预算、文件改写复核和不等待执行进程的收尾行为；成功、失败或 `still_running` 均不改变两个文件的读取范围，`execute_valid` / `fallback_files` 仅作诊断。真实应用启动始终剔除 `ELECTRON_RUN_AS_NODE`。`DEEP_LEGENDS_STARTUP_PREWARM=0` 仍关闭全部预热。PID 行首前缀、微秒时间戳及真实启动计时保留；暂存目录执行方案仍无备用开关。详见 [执行预热默认关闭验收报告](docs/history/ACCEPTANCE-REPORT-R83-READ-ONLY-DEFAULT.md)。

## 客户端兼容说明

国服客户端本地接口没有面向第三方提供稳定性承诺，因此每次版本更新都可能改变端点或字段。本工具会交叉核对多个只读端点，并在不确定时停止计算。首次公开发布前必须在真实国服 Windows 客户端上逐项验证 Riot Client aliases 读取、SGP summoner-ledge 跨服读取、League Client item-sets 写入及各自的失败降级；若界面列出待核对条目，应人工核对官方公告、客户端名称与皮肤 ID，不能放宽为自动模糊匹配或未经验证的名称纠错。

好友观战暂不提供：`/lol-spectator/v1/spectate/launch` 属于未承诺稳定性的私有契约，当前仓库和真机记录都没有可核验的请求体与失败响应，不能仅凭端点名称猜测后向客户端发写请求。回放继续使用本机客户端的 metadata/download/watch 链路，只支持客户端认可的当前分区、当前版本对局；韩服 gameId 不能由国服客户端直接换取 ROFL，项目也没有跨区回放 CDN 凭据、ROFL 元数据转换或版本转换能力，因此不会把韩服战绩错误标成可在国服播放。

## 隐私与安全

- 不要求 QQ 账号、密码或扫码登录。
- 不调用任何合成、分解、兑换或购买接口。
- 默认只读取玩家资料、排位、英雄熟练度、最近战绩、当前对局、好友分组与在线状态、皮肤目录、库存、战利品和待领取奖励。好友数据只读，不提供添加、删除、改备注或发消息。
- 默认只在玩家明确点击后调用客户端写操作：新建一页可编辑符文并设为当前页；创建或更新 Deep Legends 自己的客户端装备方案；下载或启动所选对局回放；在“工具 › 生涯”应用生涯背景皮肤、聊天状态/签名/展示段位，或经二次确认清理头像框/勋章/旗帜/表情轮盘；在“工具 › 领奖”逐项领取奖励、任务与活动奖励；在“工具 › 维护”明确点击后执行客户端界面维护、关闭客户端、断开连接或切换当前设置文件的只读属性，其中关闭客户端会二次确认。设置文件写前会校验目标位于当前安装目录且不是符号链接。符文与装备方案写入只允许发生在英雄选择阶段；符文点击后直接新建，不弹二次确认，页名固定带“[DL] ”前缀。页数已满时会删除本工具此前创建的、带精确“[DL] ”前缀且未被客户端显式标记为不可删除的最旧符文页来腾位置，每次最多回收 5 页；绝不删除其它符文页，也不更新或覆盖任何已有页。没有可回收页面时停止写入并明确提示。
- “工具 › 自动”的九条流程规则默认全部关闭并可逐条关闭：接受对局、再来一局、断线重连、结算点赞、跳过任务庆祝、阵营位置播报、房主转交、邀请处理与一次性开始匹配。点赞不会投给敌方；点赞期间快速下一把会顺延；取消匹配后不会自动重排。“工具 › 征召”的总开关、各模式禁用/选用、备战席和换英雄请求同样默认全部关闭；写入只发生在英雄选择阶段，英雄全部不可用或检测到手动接管时不会强制提交。只有“工具 › 生涯”中用户另行保存的签名/展示段位登录重设会在连接后延时 2 秒重放，手动操作可抢占。这些自动写入请求只发往 `127.0.0.1` 的本机客户端。
- 除下述由用户发起的公开玩家查询、英雄统计与静态图片读取外，不向外部服务器发送本机库存、客户端令牌或客户端图片；当前登录账号的稳定标识不会返回渲染页面。
- 国服跨服搜索只在本机回环地址连接 `RiotClientServices` 与 League Client；Riot Client aliases 令牌只用于解析被查询的 Riot ID，League Client 的 league-session / entitlements 令牌只发往固定腾讯 SGP 子服域名。两类令牌不会互换、写盘、进入 URL 或返回前端。
- 查询韩服玩家时，本地服务向固定的 Riot 官方接口域名（`asia.api.riotgames.com`、`kr.api.riotgames.com`）发送被查询的 Riot ID 与构建时注入的 API Key；若只填了名称、官方接口返回未找到，才会再向 `op.gg` 公开搜索补全编号。两类请求都不携带本机账号、Cookie 或客户端令牌，并走“英雄数据网络”里配置的同一代理通道。API Key 属于开发者个人凭据，请勿公开分发含 Key 的构建物。韩服只填名称时，还会向 OP.GG 公开搜索发送名称与大区以补全编号，同样不携带本机账号或客户端令牌。
- 为生成绝活哥符文推荐，本地服务会在英雄选定后，把从 OP.GG 韩服专家榜取得的第三方玩家 Riot ID 发送给 Riot 官方接口，并读取这些玩家的公开对局以提取目标英雄的实际符文。这不是用户主动搜索该玩家触发的查询；请求不携带本机账号、Cookie 或客户端令牌，结果按英雄在进程内缓存 6 小时。没有配置 Riot API Key 时直接返回空结果，不发起这条外部请求。
- 打开韩服玩家总览时，本地服务还会向 `op.gg` 的公开召唤师页发送**被查询玩家**的 Riot ID 与 PUUID，换取该页每场对局的平均段位（Riot 官方接口按人查询排位会超出配额，无法覆盖十人）。结果按玩家在内存中缓存 90 秒，请求同样不携带本机账号、Cookie 或客户端令牌，并走同一代理通道；任一环节失败都静默降级，战绩卡的“平均段位”一行显示“—”，不影响战绩本身。当前登录的国服服务器改由本机客户端逐人查询，不向任何外部服务发送数据；跨服不查询排位，平均段位显示“—”。
- “英雄”页只向固定 OP.GG、腾讯官方图片与 Riot Data Dragon 公共地址请求韩服统计和静态图片，不附带账号信息、客户端 Cookie、LCU 令牌或收藏数据；英雄图标与原画优先走国内腾讯官方图片域名，失败时自动回退 Data Dragon，已连接客户端时则优先直接读取本机客户端资源；图标按页面可见范围懒加载，公共代理图片另外缓存于 `champion-images`（7 天新鲜、额外 30 天过期回退，最多 2048 项 / 64MiB）。首次打开玩家页后空闲 3 秒，按 OP.GG 排位热门英雄样本的装备出现次数预热最多 120 张当前补丁最终图标，并发 6；前台操作会取消预热，不预下载全量资源包。
- 普通皮肤和炫彩图片直接从本机已登录客户端读取；查看臻彩时按炫彩 ID、皮肤原画在客户端全部读取失败时按皮肤 ID，本地服务向固定的腾讯官方图片域名请求对应公开原画，不携带账号信息、Cookie、LCU 令牌或收藏数据。
- 桌面渲染页关闭 Node.js 集成，启用上下文隔离和沙箱；本地页面同时使用随机会话令牌、HttpOnly Cookie、严格 CSP、权限拒绝和导航白名单。
- 状态 API 只返回显示名称、等级等界面所需信息，不返回 PUUID、AccountID 或 SummonerID。战绩页面中的玩家跳转使用仅当前进程有效的匿名引用，稳定玩家标识不会发送给渲染页面。
- LCU 临时令牌不写入 URL、历史、诊断或日志；只放在进程内存和本机请求的 Authorization 头中，断开或退出时清空。
- “工具 › 领奖”扫描的战利品、待领取奖励、任务与活动奖励明细只保存在进程内存中，不写入磁盘；关闭或刷新页面、或断开客户端后即丢弃。
- 战利品历史只保存带随机设备盐的账号摘要、皮肤 ID/名称和奖池元数据，不保存战绩、对局参与者、客户端令牌或稳定账号标识。公开韩服查询另使用有界缓存：`riot-matches` 保存不可变公开对局 JSON（包含该对局参与者的公开 Riot ID/PUUID），最多 600 场 / 128MiB；`riot-identities` 保存公开身份解析（15 分钟）与召唤师资料（5 分钟），最多 256 项 / 4MiB，过期不回退旧资料。文件名使用哈希，正文并非加密文件；不会写入 Riot Key、请求头、Cookie 或 LCU 数据。删除对应缓存目录可清除，后续查询会重建。
- 自定义奖池、历史和脱敏诊断默认保存在 `%LOCALAPPDATA%\\LOLLootAssistant`，文件数量和大小受限。
- 退出客户端、切换账号或刷新失败后，当前快照与图片缓存会立即失效，不继续显示旧账号结果。

### R75 公开赛事数据边界

职业符文的两个固定外网域名是 `esports-api.lolesports.com` 与 `feed.lolesports.com`，复用项目代理。前者仅使用赛事网站公开 `x-api-key`，不是 Riot 开发者密钥；请求不携带 Cookie、本地令牌、账号 PUUID 或 Riot Key。`pro-runes-v1` 磁盘目录保存公开比赛索引、终局、符文装备以及经名单核对的公开 esportsPlayerId 映射，不保存本机账号信息。终局装备不是出装顺序。


## 发布流程

1. 同步 `desktop/package.json`、锁文件和构建脚本的版本号，在 `CHANGELOG.md` 顶部新增 `## 版本 — 日期` 一节。更新弹窗的内容仅取该节的 `### 新增 / ### 优化 / ### 修复` 和列表。
2. 执行不含个人 Key 的完整构建（包含 R80 安装/卸载外壳）：Windows 使用 `./build-desktop-windows.ps1 -Version 0.12.1 -KeyMode public`，macOS 使用 `DEEP_LEGENDS_KEY_MODE=public bash build-desktop.sh 0.12.1`。随后运行 `node scripts/make-release.cjs`。脚本核对 `dist/desktop/release-build.json` 中的 public 模式、源码指纹、后端和 Setup EXE 的 SHA-256；缺失记录、private 包或构建后被替换的文件均拒绝生成发布资产。这份本机构建记录不上传。脚本默认使用当前源码指纹，也可在命令末尾指定已验证的 12 位构建指纹。请核对 `dist/release/SHA256SUMS.txt`；Windows 可用 `Get-FileHash`，macOS 可用 `shasum -a 256`。
3. 在 GitHub 仓库 `LLYY0418/Deep-Legends` 创建 `v<version>` Release，**上传 `dist/release/` 中全部三个文件**：安装版 EXE、`latest.json`、`SHA256SUMS.txt`。EXE 的发布名由脚本改为无空格版本。`latest.json` 缺失会导致客户端无法发现更新，不能只上传 EXE。公开发布前沿用本项目的凭据边界：不得公开分发内置个人 Riot API Key 的构建物。

更新检查使用 `https://github.com/LLYY0418/Deep-Legends/releases/latest/download/latest.json`，不使用 GitHub API。安装版启动后静默检查一次，此后每 6 小时检查；用户点击后才下载和安装。开发构建 `version=dev` 禁用更新。便携版及低于清单 `minSupported` 的版本只提供发布页入口。

更新缓存位于本机数据目录的 `update-manifest.json`，下载文件位于 `updates/`。如公共镜像失效，可关闭程序后在同一目录写入 `update-settings.json`，例如 `{"mirrors":["","https://ghfast.top/","https://gh-proxy.com/","https://ghproxy.net/"]}`；空字符串表示直连，其余必须是以 `/` 结尾的 HTTPS 前缀。亦可通过已鉴权的 `GET/POST /api/update/settings` 读取或保存；修改后会在下一次检查/下载使用。接口继承本地会话鉴权，更新请求不携带 LCU、Riot 或用户账号凭据。

发布前仍需在 Windows 真机验证更新检查、下载、安装及失败回退。

### 韩服查询与资源缓存（R89）

韩服总览、当前对局和赛季汇总在已知完整 Riot ID 时同时发起。首次总览只发起一轮设置场数（默认 20）的请求，通过同一个 NDJSON 响应先显示已就绪的 5 场，再补齐其余场次。429 保留现有战绩，按 Retry-After 静默重试；500/503 仍显示真实失败。诊断分别记录详情来自内存、磁盘和网络的数量。历史赛段通过既有后台事件补齐。目录请求失败后 30 秒重试；目录到达会更新已经存在的战绩卡图标。总览页只展示玩家、生涯与战绩信息，装备推荐通过英雄页或对局页查看。

`DEEP_LEGENDS_RIOT_MATCH_CONCURRENCY` 默认 8，个人 Key 最多 8；仅配置 `DEEP_LEGENDS_RIOT_KEY_TIER=production` 后允许最高 20，并不会放宽本地 15 次/秒、90 次/2分钟护栏。`DEEP_LEGENDS_ITEM_PREWARM=0` 可关闭后台图标预热。身份缓存有时效，因此刚改名或更新等级、头像后可能短暂显示缓存内容。

执行记录、诊断样本与复测脚本见 [R89 验收账本](docs/r89-execution-ledger.md)。

### 斗魂实时分组与对局刷新（R90）

Loading（GameStart）即按客户端 session 顺序尝试小队分组，不依赖 2999；进入游戏后优先按游戏进程名单顺序分组，并用选人阶段记住的自身小队核对；中途打开应用时允许未核验的顺序分组。列表显示“小队 1、2……”，暂不使用吉祥物名。游戏进程有 18 人、客户端只有 17 人时保留完整名单的队伍边界，可显示一队 2 人、其余各 3 人。Loading 已获得的有效分组也可在同局缺人时按玩家身份沿用；没有完整边界依据的 17 人名单不硬切。

完整实时快照整局复用；手动刷新、游戏变化和阶段变化会失效。不在对局页时不再因同阶段事件重载名单。切回前台仍核对客户端阶段。赛后写入 `arena_group_truth_check`，分别检验队友划分与小队编号映射，供后续真机核验使用。实现、变异测试及尚待真机验证的项目见 [R90 执行账本](docs/r90-execution-ledger.md)。

### R91 工单与加载阶段补充

生涯段位缺省为未定级；斗魂统计使用整数伤害/承伤和独立颜色，玩家行隐藏段位。实时战绩刷新保留已读内容与未变化的 DOM，首次加载仍显示骨架。只有 wildcard 禁用必须先确认亮出的路径，客户端清空已确认英雄才保留锁定；普通路径清零会让位，队友已选/已禁用的不可用候选仍可顺延，主动换成其他英雄也立即让位。保存自动规则后按当前阶段立即重评估。逐项实现、测试、截图和仍需真实客户端验证的项目见 [R91 补充执行账本](docs/r91-addendum-execution-ledger.md)。

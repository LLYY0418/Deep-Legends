# Deep Legends

Windows 本地英雄联盟助手。无需启动游戏客户端即可联网查看韩服英雄梯度、符文、出装和海克斯推荐；玩家正常登录国服客户端后，还可在本机查看召唤师生涯、最近战绩、实时对局、皮肤收藏和三合一奖池。绝大多数功能只读取公开数据或客户端；只有玩家明确点击“应用符文”“应用装备方案”或“回放”，或在设置中开启自动接受对局、再来一局、断线重连时，才会向本机客户端发送对应操作。

> 本项目不是腾讯、Riot Games 或英雄联盟官方产品，也不提供自动合成、分解、购买或账号登录功能。

## 直接运行（桌面客户端）

提供三种形态，功能完全相同，按习惯任选其一：

1. **安装版（推荐）**：下载并双击 `dist/desktop/Deep Legends Setup.exe`，按向导安装到用户目录（无需管理员权限，可自选安装位置），自动创建桌面与开始菜单快捷方式。安装版每次启动直接运行安装目录中的程序，没有任何释放步骤；卸载入口在“设置 → 应用”。
2. **便携版**：下载并双击 `dist/desktop/Deep Legends.exe`。首次启动会把程序释放到本机缓存目录 `%LOCALAPPDATA%\Deep Legends`（期间显示解压进度窗口，约几秒），之后每次双击都直接从缓存秒开。版本升级会自动清理旧缓存并重新释放；删除该目录即可完全清除程序文件。
3. **ZIP 解压版**：解压同目录的 `.zip`，运行其中的 `Deep Legends.exe`，不经过首次释放步骤。

启动后先出现启动页，本地数据服务加载完成再显示主界面。如果英雄联盟尚未运行，仍可直接使用“英雄”页；也可在未连接首页选择程序检测到的 TCLS、WeGame 或 Riot 客户端入口，登录并进入大厅后会自动读取收藏。

窗口可以自由缩放。左侧一级导航为“总览 / 英雄 / 对局 / 收藏”，连接状态与设置固定在底部；收藏顶部使用紧凑的横向二级导航容纳皮肤、账户和三合一奖池，收藏指标固定显示在右侧，本地历史与奖池数据来源位于奖池页签。页面会随窗口宽度调整；顶部提供召唤师搜索（国服可从艾欧尼亚、黑色玫瑰、联盟一区至五区、峡谷之巅和体验服中选择具体服务器，韩服单独选择；名称与 # 编号分栏，粘贴完整 Riot ID 自动拆分；韩服可只填名称，编号由公开搜索补全后再精确查询）与带在线人数徽标的“好友”按钮，主题、界面密度、默认页、英雄默认位置、战绩展示数量与默认筛选、实时对局排序和刷新间隔、自动接受对局 / 再来一局 / 断线重连、隐私遮罩及回放操作确认按分类页签收纳在“设置”。离开某个主页面后再进入，该页的页签与筛选项会还原为默认；总览页内在玩家页签之间来回切换时，各页签的筛选、战绩展开与详情页签互相独立保留。

桌面主程序会隐藏启动内置的本地数据服务。服务只监听随机的 `127.0.0.1` 本机端口，启动握手使用每次随机生成的会话令牌；令牌只保存在进程内存中，不写入磁盘，也不会上传服务器。

### Windows 安全提示

构建脚本支持使用可信代码签名证书文件进行 Authenticode 签名，并在构建后生成 SHA-256。没有提供证书时会明确生成未签名开发版，Windows SmartScreen 仍可能显示“未知发布者”；代码本身无法绕过这一信誉机制。

公开分发建议同时提供：

- 受信任证书签名的安装版与便携版 EXE；
- 包含 EXE 的 ZIP；
- `SHA256SUMS.txt`；
- 发布页中的版本说明和扫描结果。

## 功能

- “英雄”无需登录客户端即可按需联网读取 OP.GG 韩服单/双排梯度及详情，并提供全部、上单、打野、中单、下路、辅助位置和最强王者至铂金及以上段位切换。搜索支持中文、英文、拼音、首字母缩写与常见外号；海克斯大乱斗页展示英雄梯度、完整强化符文目录、描述和适合英雄，详情优先呈现推荐海克斯，再复用召唤师技能、技能顺序和出装组件；斗魂竞技场页展示英雄梯度与三人队伍协同榜（平均名次、第一名率、选用率、胜率），详情提供推荐三人队伍与推荐海克斯。最强王者等高分段样本不足时，整页或仅对抗数据回退到翡翠以上并在界面标注实际口径。
- “总览”按当前召唤师和新打开的玩家标签展示单排/双排、灵活组排、英雄胜率、位置偏好、熟练度、过去 30 天排位、最近 30 天同场玩家、活跃时段及最近战绩；排位使用官方段位徽章，当前登录账号的标签固定第一并以金色高亮。战绩卡与对局详情附带单场相对评分和 MVP / SVP 标记：按 KDA、参团率、伤害、经济、补刀和视野相对同场玩家加权计算，仅供参考，不代表官方口径。在总览页点击玩家名称会打开可关闭的新标签；在对局页或英雄详情页点击玩家名称则在当前页面以覆盖层展示总览，左上角“返回”回到原页面。国服完整对局数据（双方十人）通过腾讯官方 SGP 网关读取，令牌来自本机已登录客户端。
- 顶部搜索框支持国服具体子服务器与韩服：国服先通过本机 `RiotClientServices` 的全局 aliases 接口把精确 `游戏名#编号` 解析为内部 PUUID，再使用当前已登录 League Client 提供的 league-session 令牌向所选腾讯 SGP 子服读取召唤师和战绩；两套本地服务的端口与令牌彼此独立，不会写盘或返回渲染页。国服排位接口只能读取当前登录服务器，打开其他子服玩家时排位卡会明确显示“跨服暂不支持排位”。韩服玩家通过 Riot 官方开发者 API 精确查询，段位、熟练度、最近战绩与国服玩家使用同一套总览界面。韩服允许只填名称：官方接口找不到时，本机服务会向 OP.GG 公开搜索补全编号，再回到 Riot 查询。API Key 以密文形式内嵌：先运行 `go run . -encrypt-riot-key "RGAPI-你的key"`，再用 `-RiotAPIKeyCipher` 参数（或环境变量 `RIOT_API_KEY_CIPHER`）在构建时注入，源码中的 `riotAPIKeyCipher` 变量本身永远留空，不会提交到仓库（密文只能防止从源码中直接扫出明文，不能阻止拿到 EXE 后抓包或逆向提取，请自行评估分发范围；泄露后可到开发者门户重置）。官方 API 不覆盖国服；汇总统计基于当前已读取的战绩样本，单场详情在本机内存缓存以节省接口配额。
- 服务器归属规则：韩服与每个国服子服务器互不相通。搜索栏按所选服务器查询；点击页面内出现的玩家名称时沿用当前页面所属的具体服务器，时间线、分页和异步缓存也保持相同作用域；跨服排位与依赖逐人排位的平均段位不受客户端接口支持，分别明确显示能力边界或“—”。英雄详情页的玩家榜来自 OP.GG 韩服数据、固定按韩服打开。玩家页签与总览头部会标注“艾欧尼亚”“黑色玫瑰”等具体子服或“韩服”。隐藏名称和主播模式只遮罩身份显示；英雄选择阶段的标准 `obfuscatedPuuid` 在后端本地恢复为内部引用，然后与普通玩家使用相同的可用数据管线。
- 战绩可直接筛选单排/双排、灵活组排、海克斯大乱斗与斗魂竞技场，其余队列在“更多模式”中选择。单场卡片可展开双方概览、队伍分析和构建：队伍分析用红蓝双色对比条呈现击杀、金币、伤害、视野等六项指标；构建页展示结算装备、按分钟分组的装备购买路线（含出售记录）、真实的技能加点顺序（主升/副升摘要）和完整符文树。装备路线与技能加点来自对局时间线：国服优先读取本机客户端，其次官方 SGP 网关；韩服来自 Riot 官方 timeline 接口；读取不到时明确降级，不用英雄默认顺序代替。回放按钮点击后直接交由英雄联盟客户端处理，需要先下载的回放会在下载完成后自动开始播放（官方回放仅保留当前客户端版本的对局）。
- 战绩卡左侧是模式、相对时间、结果与时长；中间是英雄头像、召唤师技能、主系基石与副系符文、K/D/A 和单场评分，下方按客户端原始槽位展示装备与饰品（空槽保留占位框），并附评分排名、MVP / SVP、多杀与零阵亡徽章；再向右三行数据分别是击杀参与率、补刀（悬停可见小兵与野怪拆分及分均补刀）和本场平均段位；最右列出本场玩家，点击即可打开该玩家总览。卡片按战绩栏自身宽度自适应，窄窗口下依次收起玩家列表并把数据行改为横排。
- 单双排与灵活组排的战绩会显示这一场的胜点（LP）增减。官方接口（本机客户端、Riot、SGP）都不提供单场胜点变化，本地服务改为在对局结算时读取排位数据并与赛前基线比较得出。`lp-history.json` 使用 `schemaVersion: 1`：基线键和游戏记录都只保存由本机随机盐与账号内部标识计算的 SHA-256 前 16 位小写十六进制 `accountHash`，不保存 PUUID；文件以 `0600` mode 参数原子写入，最多保留 400 条最新游戏记录。旧 schema、非法哈希或损坏文件会被清空重写，不迁移其中的明文标识。因此只有助手运行期间打的排位才有这个数字，更早的历史对局无法回溯，其他模式不显示。
- 平均段位：当前登录的国服服务器通过本机客户端逐人查询本场参与者的排位后取平均，界面按卡片懒加载回填并在本机缓存 10 分钟；跨服不受排位接口支持，显示“—”。韩服逐人查询会超出 Riot 接口配额，改为按开局时间与时长匹配 OP.GG 公开对局数据里的平均段位。大师及以上附带平均胜点。取不到时该行显示“—”，不以推断值代替。
- 斗魂竞技场按 21 人、3 人一队完整展示：战绩卡右侧按小队分列全部玩家、第一名小队高亮，左侧显示本队名次而非胜负；展开后概览与队伍分析都按名次分组呈现七支小队。击杀参与率与评分中的参团维度按本小队三人的击杀合计计算，不使用在该模式下无意义的红蓝方汇总。
- 顶栏“好友”按钮打开右侧只读好友面板：分组、顺序、折叠初始态与备注完全来自本机客户端，离线好友统一归入底部“离线”组并显示最近在线时间，组内按游戏中、在线、离开、手机在线排序；游戏中的好友显示队列、英雄与实时时长，点击任意好友即在总览页打开其战绩。面板不提供好友增删改或消息功能，未连接客户端时按钮禁用。
- “对局”在英雄选择或游戏进行时展示双方玩家、当前队列的近期胜负/胜率/KDA，可按 10 / 15 / 30 / 60 秒自动刷新，并支持按位置、KDA 或胜率排列玩家。“详情”页签中每名玩家的最近战绩只统计当前队列，点击玩家名称跳转到总览页查看完整生涯。OP.GG 综合符文已经接入；绝活哥符文使用独立懒加载链路：取 OP.GG 韩服专家榜前两名玩家，经 Riot 官方接口在每人最近 10 场对局中最多检查 8 场，只返回目标英雄且主系、副系和符文完整的真实配置，同时标注玩家、段位、英雄场次、对局时间与胜负；结果按英雄在进程内缓存 6 小时，取不到时保持空态，不用其它英雄或聚合数据冒充。职业选手推荐位因缺少可核验的数据源仍明确保持不可用。客户端自身返回的推荐符文可作为备用。英雄选择阶段点击“应用到客户端”会直接新建一页以“[DL] 英雄名 · 推荐来源”命名的符文并设为当前页；若客户端页数已满，只读取页面名称、删除许可、修改时间与 ID，并最多删除 5 个本工具此前创建的、名称带精确“[DL] ”前缀且未显式标记为不可删除的最旧页面来腾位，绝不删除、更新或覆盖其它符文页。没有可回收页面时停止并提示玩家手动删除一页；改版前没有前缀的旧页面不会迁移或回收。出装推荐旁的“应用装备方案”只在英雄选择阶段启用，点击后才创建或更新 Deep Legends 自己的客户端装备方案，并保留用户已有方案。
- 兼容性边界：Riot Client 的 `aliases/v1/lookup`、腾讯 SGP 的 `summoner-ledge` 和 League Client 的 `lol-item-sets` 都是没有官方稳定性承诺的客户端私有契约。目前只有 macOS 上的本地 mock 自动测试，尚未完成 Windows 国服客户端真机验证；在三条链路逐项通过真机烟雾测试前，它们都按实验性能力处理，不能作为已完成的发布验收项。读取失败会明确降级，跨服失败不会回退到当前服务器数据；装备方案写入仍要求英雄选择阶段和玩家明确点击。
- 收藏页提供已拥有、全部皮肤和全部炫彩三个视图；已拥有默认首先展示。
- 战绩展示数量可设为每批 10 / 20 / 30 / 40 / 50 场；滚动到列表末尾会按同一批次自动继续读取。
- 全部皮肤通常按英雄分组；选择品质筛选或品质排序时改为按品质和神话子类分组。已拥有皮肤保持原画，未拥有皮肤置灰并显示锁。
- 全部皮肤可按英雄熟练度、皮肤数量、英雄名、品质或获取时间排列。获取时间模式以每位英雄最近获得的已拥有皮肤决定英雄分组顺序。
- 全部炫彩与普通皮肤、三合一奖池分别核对：国服臻彩按腾讯官方臻彩藏品清单与客户端炫彩 ID 交叉识别，在普通炫彩上方使用高清横版独立原画，可单独关闭“显示臻彩”。普通炫彩按所属皮肤分行横向平铺；普通滚轮始终上下滚动页面，触控板横滑、`Shift + 滚轮`或行内左右箭头用于横向浏览。默认同时展示已拥有和未获取项目，可关闭“显示未获取”。
- 皮肤和炫彩详情支持上一款、下一款与全屏原画；皮肤在同英雄内切换，臻彩在臻彩之间切换，普通炫彩在同一所属皮肤内切换。
- “三合一奖池”提供奖池目录、清单上传和本地历史三个页签，目录可分别查看已拥有与未拥有皮肤，并按精简后的奖池品质筛选。
- 搜索皮肤名、英雄名和 ID，并按英雄、品质、名称、获取时间或 ID 排序。
- 皮肤详情按需读取 RP 价格、库存 `purchaseDate` 和加载界面边框所有权；缺少可核验字段时明确降级，不推测结果。
- 普通皮肤与炫彩预览使用本机客户端备用路径，图片失败会自动重试，本机路径全部失败时按皮肤 ID 从固定的腾讯官方图片域名降级读取横版原画；臻彩独立插画按需从固定的腾讯官方图片域名读取并在本机缓存。客户端提供动态 WebM 时优先播放，并将“联盟不朽”任务皮肤形态作为独立原画条目展示。
- 库存来源状态、目录指纹、奖池哈希和映射完整度写入本机脱敏日志；测试用核对详情不占用正式客户端导航。
- 客户端启动、收藏变化或手动重新读取时会自动更新界面并显示读取进度。
- “账户与物品”只读页：按精粹、钥匙、皮肤、其他战利品和奖励分区展示；皮肤类库存会按稳定皮肤 ID 显示客户端中文名称。
- 只读接口能力检测：客户端不支持的附加端点会单独降级，不影响皮肤剩余计算。
- JSON、CSV、离线 HTML 导出；CSV 会防止公式注入。
- 最近 30 份本地脱敏快照位于“三合一奖池 / 本地历史”，同账号、同奖池版本之间可以比较变化。
- 导入并显式切换 TXT、单列 CSV 或 JSON 自定义奖池；每份清单都有规范化 SHA-256。
- 原生桌面窗口、Windows 任务栏图标、可收起图标侧边栏、紧凑模式和响应式布局；主题在设置中选择：自动（昼夜切换）、浅色、海克斯黑金、寒冰蓝、翡翠绿、星域紫、血月红、极光青、纯黑 OLED。背景保持中性深色，主题色只出现在主色、选中态和描边上。
- 设置中的便捷选项可在本机客户端已连接时自动接受对局、结算后再来一局、以及掉线后重连；默认全部关闭，开关保存在本机数据目录。
- 未连接时优先检测并启动桌面或开始菜单中的英雄联盟、WeGame、Riot Windows 快捷方式，找不到时才使用已验证的安装目录；接口不接受任意程序路径。

## 准确性规则

- 奖池原图结构确认有 554 个非空条目；内置清单已经人工最终确认并核验为 554 个唯一稳定皮肤 ID，名称只作审计标签。
- 内置奖池直接用稳定皮肤 ID 核对当前客户端，避免改名、错别字或相似炫彩名称导致错配；自定义纯名称清单仍严格要求唯一匹配。
- 已拥有库存只接受明确的 `owned=true`、`OWNED`、`PURCHASED` 或专用皮肤库存端点中的实际条目。
- `AVAILABLE`、免费轮换、商城可购买状态不视为已拥有。
- 优先采用完整显式收藏来源；只有专用 `CHAMPION_SKIN` 实际库存完整包含至少两份显式来源时，才允许用库存补齐显式接口遗漏。成功空集合是合法的零库存结果。
- HTTP 404 视为当前客户端不支持该端点；临时失败、无效 JSON、未知 ID、单一来源或任意集合冲突都会停止计算。
- 皮肤目录只读取普通皮肤对象，并同时按嵌套层级、炫彩分类/父皮肤字段和 ID 范围排除炫彩及其他库存附属项；基础皮肤不计入收藏目录。
- 获取时间只接受皮肤库存明确返回的 `purchaseDate` / `purchased` 等购买时间字段，并交叉合并三路库存来源、校验时间范围；未拥有皮肤不显示获取时间。
- RP 价格只接受商店皮肤详情中明确标记为 RP 的金额；含糊或互相冲突的价格字段不会展示为确定价格。
- 边框必须先由对应皮肤的静态 `skinAugments` 证明存在，再以边框内容 ID 与专用库存精确匹配；仅有边框素材不等于账号拥有。
- 目录必须达到皮肤/英雄数量下限，并为每个活动英雄包含对应基础皮肤；目录指纹会写入可导出的本机脱敏日志。
- 名称近似匹配只用于给出修正建议，不会自动计入奖池。
- 只有 554 个奖池条目全部唯一映射成功时才显示剩余结果；否则停止计算并列出待核对项。

计算公式：

```text
三合一剩余 = 国服公告奖池皮肤 ID 集合 − 当前账号已拥有皮肤 ID 集合
```

奖池来源和原图位于 [`data/README.md`](data/README.md)。

## 从源码构建桌面客户端

要求 Go 1.24 或更高版本、Node.js 22 或更高版本。桌面外壳使用 Electron 43 和 electron-builder 26；WebSocket 事件订阅使用固定版本的 `github.com/gorilla/websocket v1.5.3`。Node 与 Go 的依赖校验分别记录在 `desktop/package-lock.json` 和 `go.sum`。

Windows PowerShell：

```powershell
./build-desktop-windows.ps1
```

指定版本并使用证书库中的代码签名证书：

```powershell
./build-desktop-windows.ps1 -Version "0.11.0" -CertificateFile "你的代码签名证书.pfx" -CertificatePassword "证书密码"
```

带上真实 Riot API Key（先用 `go run . -encrypt-riot-key "RGAPI-你的key"` 生成密文，只在自己本机构建时使用，不要提交到仓库）：

```powershell
./build-desktop-windows.ps1 -RiotAPIKeyCipher "上一步生成的密文"
# 或者用环境变量，避免密文出现在 shell 历史记录里
$env:RIOT_API_KEY_CIPHER = "上一步生成的密文"
./build-desktop-windows.ps1
```

不提供密文也能构建，只是产物里没有内嵌 Key，韩服查询需要在运行时设置环境变量 `RIOT_API_KEY` 才能用。

脚本会检查 `gofmt`、运行测试与 `go vet`、校验前端和 Electron 主进程 JavaScript，将 Go 后台编译为无命令窗口的 Windows GUI 程序，再生成安装版 `Deep Legends Setup.exe`（NSIS，用户级免管理员安装）、便携版 `Deep Legends.exe`、ZIP 解压版和 SHA-256。未提供证书时构建仍可运行，但 Windows 可能显示“未知发布者”。仓库中的 GitHub Actions 会在 Linux 运行竞态检测，并在 Windows 生成桌面发布物和校验哈希。

便携版 EXE 使用 `desktop/nsis/portable.nsi` 定制启动器替换 electron-builder 内置模板（内置模板每次启动都会把整个程序解压到 `%TEMP%` 并在退出后删除，导致每次双击都要等待解压）。定制模板改为首次启动释放到 `%LOCALAPPDATA%\Deep Legends\app-<版本>` 并保留，之后启动检测到缓存完整时直接静默运行；构建脚本会在打包前自动完成模板覆盖。Go 后端可执行文件通过 `asarUnpack` 直接随包分发，桌面壳启动时直接运行，不再在每次启动时做“读取归档 → SHA-256 校验 → 释放到用户目录”的复制。

仅构建隐藏后台服务（不含桌面窗口）：

```bash
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -buildvcs=false -trimpath -ldflags="-s -w -H=windowsgui -X main.riotAPIKeyCipher=你的密文" -o "desktop/backend/loot-service.exe" .
```

测试：

```bash
go test -race ./...
go vet ./...
node --check web/app.js
node --check web/gameplay.js
node --check web/champions.js
node --check desktop/main.cjs
node --test web/*.test.cjs desktop/*.test.cjs
```

## 客户端兼容说明

国服客户端本地接口没有面向第三方提供稳定性承诺，因此每次版本更新都可能改变端点或字段。本工具会交叉核对多个只读端点，并在不确定时停止计算。首次公开发布前必须在真实国服 Windows 客户端上逐项验证 Riot Client aliases 读取、SGP summoner-ledge 跨服读取、League Client item-sets 写入及各自的失败降级；若界面列出待核对条目，应人工核对官方公告、客户端名称与皮肤 ID，不能放宽为自动模糊匹配或未经验证的名称纠错。

## 隐私与安全

- 不要求 QQ 账号、密码或扫码登录。
- 不调用任何合成、分解、兑换或购买接口。
- 默认只读取玩家资料、排位、英雄熟练度、最近战绩、当前对局、好友分组与在线状态、皮肤目录、库存、战利品和待领取奖励。好友数据只读，不提供添加、删除、改备注或发消息。
- 默认只在玩家明确点击后调用三类客户端写操作：新建一页可编辑符文并设为当前页；创建或更新 Deep Legends 自己的客户端装备方案；下载或启动所选对局回放。符文与装备方案写入只允许发生在英雄选择阶段；符文点击后直接新建，不弹二次确认，页名固定带“[DL] ”前缀。页数已满时会删除本工具此前创建的、带精确“[DL] ”前缀且未被客户端显式标记为不可删除的最旧符文页来腾位置，每次最多回收 5 页；绝不删除其它符文页，也不更新或覆盖任何已有页。没有可回收页面时停止写入并明确提示。
- 若在设置中打开便捷选项，本机服务还会在对应客户端阶段自动调用：接受对局（ReadyCheck）、再来一局（EndOfGame）、断线重连（Reconnect）。这些请求只发往 `127.0.0.1` 的本机客户端，可随时关闭。
- 不向外部服务器发送召唤师信息、库存、客户端令牌或客户端图片。
- 国服跨服搜索只在本机回环地址连接 `RiotClientServices` 与 League Client；Riot Client aliases 令牌只用于解析被查询的 Riot ID，League Client 的 league-session / entitlements 令牌只发往固定腾讯 SGP 子服域名。两类令牌不会互换、写盘、进入 URL 或返回前端。
- 查询韩服玩家时，本地服务向固定的 Riot 官方接口域名（`asia.api.riotgames.com`、`kr.api.riotgames.com`）发送被查询的 Riot ID 与构建时注入的 API Key；若只填了名称、官方接口返回未找到，才会再向 `op.gg` 公开搜索补全编号。两类请求都不携带本机账号、Cookie 或客户端令牌，并走“英雄数据网络”里配置的同一代理通道。API Key 属于开发者个人凭据，请勿公开分发含 Key 的构建物。韩服只填名称时，还会向 OP.GG 公开搜索发送名称与大区以补全编号，同样不携带本机账号或客户端令牌。
- 为生成绝活哥符文推荐，本地服务会在英雄选定后，把从 OP.GG 韩服专家榜取得的第三方玩家 Riot ID 发送给 Riot 官方接口，并读取这些玩家的公开对局以提取目标英雄的实际符文。这不是用户主动搜索该玩家触发的查询；请求不携带本机账号、Cookie 或客户端令牌，结果按英雄在进程内缓存 6 小时。没有配置 Riot API Key 时直接返回空结果，不发起这条外部请求。
- 打开韩服玩家总览时，本地服务还会向 `op.gg` 的公开召唤师页发送**被查询玩家**的 Riot ID 与 PUUID，换取该页每场对局的平均段位（Riot 官方接口按人查询排位会超出配额，无法覆盖十人）。结果按玩家在内存中缓存 90 秒，请求同样不携带本机账号、Cookie 或客户端令牌，并走同一代理通道；任一环节失败都静默降级，战绩卡的“平均段位”一行显示“—”，不影响战绩本身。当前登录的国服服务器改由本机客户端逐人查询，不向任何外部服务发送数据；跨服不查询排位，平均段位显示“—”。
- “英雄”页只向固定 OP.GG、腾讯官方图片与 Riot Data Dragon 公共地址请求韩服统计和静态图片，不附带账号信息、客户端 Cookie、LCU 令牌或收藏数据；英雄图标与原画优先走国内腾讯官方图片域名，失败时自动回退 Data Dragon，已连接客户端时则优先直接读取本机客户端资源；图标按页面可见范围懒加载，并交由浏览器短期缓存，不预下载全量资源包。
- 普通皮肤和炫彩图片直接从本机已登录客户端读取；查看臻彩时按炫彩 ID、皮肤原画在客户端全部读取失败时按皮肤 ID，本地服务向固定的腾讯官方图片域名请求对应公开原画，不携带账号信息、Cookie、LCU 令牌或收藏数据。
- 桌面渲染页关闭 Node.js 集成，启用上下文隔离和沙箱；本地页面同时使用随机会话令牌、HttpOnly Cookie、严格 CSP、权限拒绝和导航白名单。
- 状态 API 只返回显示名称、等级等界面所需信息，不返回 PUUID、AccountID 或 SummonerID。战绩页面中的玩家跳转使用仅当前进程有效的匿名引用，稳定玩家标识不会发送给渲染页面。
- LCU 临时令牌不写入 URL、历史、诊断或日志；只放在进程内存和本机请求的 Authorization 头中，断开或退出时清空。
- 本地历史只保存带随机设备盐的账号摘要、皮肤 ID/名称和奖池元数据，不保存战绩、对局参与者、客户端令牌或稳定账号标识。
- 自定义奖池、历史和脱敏诊断默认保存在 `%LOCALAPPDATA%\\LOLLootAssistant`，文件数量和大小受限。
- 退出客户端、切换账号或刷新失败后，当前快照与图片缓存会立即失效，不继续显示旧账号结果。

⑥一位战绩

该英雄最近拿到第一名的对局
「高手对局」= 新增后端代理 GET /api/champions/arena-first-places?championId=799&limit=10 → 上游 https://api.your.gg/kr/api/arena/champions/{id}/top-builds?limit=10（无鉴权、天然全是 subteamPlacement=1；上限 10 条；浏览器直连会 403，必须服务端代理）。
战绩卡与总览页完全同一个组件：后端把响应映射成现有的 gameplayMatch / gameplayParticipant 形状，前端调用总览页那个 renderMatch(match, playerRef, tab)（gameplay.js:1127）， 不写任何简化版战绩卡。下面这张卡的 DOM 结构和类名是照 gameplay.js:1195-1211 的输出 1:1 复刻的，CSS 直接吃 gameplay.css:302-411，本页零新增样式。
隐私红线：上游带 summonerId（Riot 加密稳定 ID），后端必须剥除，只透传 riotIdGameName#tagline；去重 me/participants 也在后端做完。
能力边界：participants[] 只有 11 个轻字段（英雄 / 名字 / subteamId / subteamPlacement），没有队友的 KDA 与出装。 这不影响卡片主体——总览页的 renderMatchPlayers() 在斗魂下本来就只画「第 N 名 + 3 个头像+名字」，字段刚好够； 受影响的只有展开详情（renderArenaMatchOverview 的伤害/承伤列会是空的），所以「高手对局」页签的卡片要禁用展开按钮并给出提示，「我的一位」页签则完全可展开。
「我的一位」= 本地 /api/gameplay/overview 结果里筛 modeGroup==='arena' && championId===当前英雄 && placement===1，无记录时走空态。
! YOUR.GG 的斗魂数据只有韩服一份（地区前缀 na/euw 返回的也是同一批韩服对局，cn 不支持）。区块标题旁需常驻来源标注，避免国服用户误认为是自己服的数据。
本次唯一要改的战绩卡逻辑：把斗魂的中部数据列填上，而不是清空。 现在 gameplay.js:1179-1181 是 if (arenaPlacement) statRows = ""， 于是 gameplay.js:1201 连 .match-stats 容器都不输出——参考站截图里的 KDA / Damage / DT 三个数，我们其实全都有，只是没渲染。
三个数的含义与我们的字段对应：KDA = 击杀/死亡/助攻 + 括号里的 KDA 比值（我们已经画在 .match-kda 里，不要在数据列重复）； Damage = 对英雄造成的伤害 = subject.damage ← totalDamageDealtToChampions； DT = Damage Taken 承受伤害 = subject.damageTaken ← totalDamageTaken。
这两个字段三条链路全都已经填好了，零后端改动：韩服 Riot riot_api.go:363-364 → 621、国服 SGP 复用同一转换（gameplay.go:930 → riot_api.go:621）、国服 LCU 兜底 gameplay.go:363-364 → 1630。 斗魂详情展开里的伤害列（gameplay.js:1353）早就在用它们，是活数据。
建议的斗魂三行（复用现成变量，不新建 CSS）：participationRow（gameplay.js:1175，斗魂下 participantGroupKey 已按小队算，口径正确） + damageRow（gameplay.js:1177，原样复用）+ 新增一行「经济」subject.gold（同样三条链路已填）。 不要放平均段位（斗魂无段位）、不要放 CS / 视野（上游恒 0）。
数值格式沿用 number()（gameplay.js:86，输出 98,209）。参考站的 29.0k 我们没有对应函数——现有 compactNumber()（gameplay.js:88）是中文「万」制， 要么接受 9.8万，要么就用千分位；不建议为此新写一个 k 制函数，会和全项目其它数字口径打架。
